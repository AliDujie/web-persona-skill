# 10 · Lene Nielsen 十步法 (10 Steps to Personas)

> 来源：Lene Nielsen《Personas - User Focused Design》第 2 版 (Springer, 2019)。
>
> Lene Nielsen 是丹麦哥本哈根 IT 大学副教授，欧洲学派 Persona 研究的代表。本书是迄今为止最系统化的 Persona 学术教材，提出"四视角分类"和"10 步法"两大贡献。本笔记基于个人学习理解整理，非原文复制。

---

## 1. 与 Mulder/Cooper 派的关系

| 维度 | Mulder/Cooper（北美派） | Lene Nielsen（欧洲派） |
|---|---|---|
| 风格 | 实战手册 | 学术系统化 |
| 角色密度 | 3-5 个 | 通常 4-7 个 |
| 叙事强度 | 中（一日叙事） | 高（小说级故事） |
| 验证方法 | 焦点小组 | 量化数据 + 焦点小组双轨 |
| 文化背景 | 美式产品开发 | 欧洲（更注重伦理与包容性） |

> 💡 **欧洲派独特贡献**：把 Persona 与**叙事学**（Narratology）和**包容性设计**结合，让角色有"人物弧光"而非平面切片。

---

## 2. 四种 Persona 视角 (Four Perspectives)

Nielsen 把目前世界上所有 Persona 实践归为四类，**承认它们各有合法性**：

### 2.1 Goal-Directed Perspective（目标导向视角）— Cooper 派

- 创始人：Alan Cooper
- 核心：用户目标驱动设计
- 优点：紧密绑定设计决策
- 缺点：忽视情绪、文化、社会上下文

### 2.2 Role-Based Perspective（角色导向视角）— Mulder/IBM 派

- 创始人：Steve Mulder, Pruitt & Adlin
- 核心：用户在系统中扮演的"角色"
- 优点：定量验证、跨部门可用
- 缺点：扁平化，缺乏深度叙事

### 2.3 Engaging Perspective（参与式视角）— Nielsen 自创

- 创始人：Lene Nielsen
- 核心：**故事讲述（Storytelling）作为方法**
- 角色像小说人物，有完整人格、背景、情绪
- 优点：团队真正"记住"并在决策中调用
- 缺点：投入大，需要叙事写作训练

### 2.4 Fiction-Based Perspective（虚构式视角）— Lean/Proto-Persona 派

- 创始人：Don Norman 提出"Ad-Hoc Persona"概念，Gothelf 发展为 Proto-Persona
- 核心：基于团队假设，无需研究即可创建
- 优点：快、便宜、启动门槛低
- 缺点：高风险偏见，必须事后验证

> 💡 **Nielsen 的中立态度**：选哪个视角取决于项目阶段和组织成熟度。她反对将任何一派绝对化。

## 3. 十步法 (10 Steps Method)

```
┌─────────────────────────────────────────────────┐
│  Phase 1: Discover（发现）                      │
│   1. Finding the users（寻找用户）              │
│   2. Building a hypothesis（建立假设）          │
│   3. Verification（验证）                       │
│                                                 │
│  Phase 2: Construct（构造）                     │
│   4. Finding patterns（识别模式）               │
│   5. Constructing personas（构造角色）          │
│   6. Defining situations（定义情境）            │
│                                                 │
│  Phase 3: Disseminate（传播）                   │
│   7. Validation and buy-in（验证与共识）        │
│   8. Knowledge dissemination（知识传播）        │
│                                                 │
│  Phase 4: Use（使用）                           │
│   9. Creating scenarios（创建场景）             │
│  10. Ongoing development（持续发展）            │
└─────────────────────────────────────────────────┘
```

### 3.1 Step 1: Finding the users
- 数据来源：现有客户数据 / 网站分析 / 用户研究 / 二手报告
- **重点**：明确"谁不是我们的用户"——边界比中心更重要

### 3.2 Step 2: Building a hypothesis
- 团队工作坊：基于已有信息提出 6-10 个假设角色
- 此步即 **Ad-Hoc Persona** 阶段
- 用便利贴墙面工作

### 3.3 Step 3: Verification
- **双轨验证**：
  - 定性：6-12 名/假设角色的深度访谈
  - 定量：200+ 样本问卷
- 假设 vs 数据偏差 > 30% 时，假设需重写

### 3.4 Step 4: Finding patterns
- 在数据中识别行为模式
- Nielsen 的方法：**叙事亲和（Narrative Affinity）**——按"故事线"聚类，而非纯属性聚类
- 例：所有"为家人安全焦虑"的用户聚为一类，无论年龄

### 3.5 Step 5: Constructing personas
- 4-7 个角色（多于 Cooper 的 1+N，少于 Mulder 的 5+）
- 每个角色配 **小说级叙事**：
  - 童年背景（与产品域相关的部分）
  - 当前生活情境
  - 与产品的相遇故事
  - 内心冲突
- 角色之间形成"角色生态"，有互动关系

### 3.6 Step 6: Defining situations
- 每个角色在 3-5 个典型情境中如何表现
- 情境维度：时间 / 地点 / 情绪 / 在场他人 / 设备
- 这是 Nielsen 与 Cooper 的最大差异——**情境**而非**任务**作为基本单元

### 3.7 Step 7: Validation and buy-in
- 与利益相关者共同审核
- 关键问题："你能想象这个人走进你办公室吗？"
- 不通过 → 回到 Step 4

### 3.8 Step 8: Knowledge dissemination
- 多媒体推广：海报 / 视频 / 工作坊 / Wiki / 录音剧
- Nielsen 实测有效：**录音剧本**（让角色用第一人称讲故事的 5 分钟音频）

### 3.9 Step 9: Creating scenarios
- 类似 Cooper 的场景三联式
- 但 Nielsen 强调 **emotional arc**（情绪曲线）
- 每个场景标注角色情绪从开始到结束的变化

### 3.10 Step 10: Ongoing development
- 季度审查
- 数据漂移监控（角色描述与新数据的偏差）
- 退役/更新决策

## 4. 叙事写作的五要素

Nielsen 的 Engaging Perspective 要求 Persona 文档具备小说级叙事质量：

| 要素 | 说明 | 示例 |
|---|---|---|
| **Character（人物）** | 内心冲突、欲望、恐惧 | "玛丽既想创业又害怕辜负父母期待" |
| **Setting（场景）** | 物理与社会环境 | "周日傍晚，玛丽在父母家厨房" |
| **Plot（情节）** | 决策点与转折 | "她打开 App 想看创业课，听到父亲走来" |
| **Conflict（冲突）** | 内/外冲突 | "怎么向父母解释这是工作而非游戏？" |
| **Resolution（解决）** | 用户期望的结局 | "App 设计应让她快速隐藏内容、保住和谐" |

> 💡 **设计含义**：当 Persona 有完整的人物弧光，团队会自发问"我们的产品如何帮玛丽走过这场冲突？"——这是平面 Persona 永远做不到的。

## 5. 包容性设计补充

Nielsen 第 2 版（2019）新增章节，强调 Persona 的伦理责任：

| 风险 | 缓解 |
|---|---|
| 强化刻板印象 | 角色之间打破单一维度（如让"足球妈妈"也有职业野心） |
| 排除边缘群体 | 引入 **Edge Persona**（边缘角色），即便不是设计目标也作为完整性检查 |
| 文化偏见 | 跨地域研究、本地化叙事 |
| 数字鸿沟 | 包含低数字技能、低收入、残障用户 |

> Microsoft Inclusive Design 的"Persona Spectrum"（永久-临时-情境性能力差异）可与 Nielsen 框架结合使用。

## 6. 何时优先使用 Nielsen 框架

| 情境 | 推荐 |
|---|---|
| 学术研究 / 论文 / 方法论严谨度审查 | ✅ Nielsen 系统化最强 |
| 团队需要"记住"并使用 Persona | ✅ Engaging Perspective 叙事力强 |
| 涉及伦理敏感、包容性要求高 | ✅ 包容性设计章节直接可用 |
| 同时处理多种 Persona 风格的争论 | ✅ 四视角分类法是中立框架 |
| 快速 MVP 创业项目 | Lean UX 即可，Nielsen 投入过大 |
