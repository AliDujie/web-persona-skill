# 02 — 定性路径：深度访谈 + 现场观察全流程

---

## 一、定性路径适合谁

- 团队规模 ≤ 20 人
- 需要深入理解用户的动机、情境、决策过程
- 时间 3-6 周，预算中等
- 对大多数产品团队来说，这是**默认且最高性价比的选择**

---

## 二、全流程概览

```
准备（W1前半）→ 招募（W1）→ 执行访谈（W2）→ Field Debrief（每天）→ 分析工作坊（W3）
```

---

## 三、准备阶段

### 3.1 明确研究问题

不是"了解用户"（太泛），而是具体的决策问题：

| 太泛 | 刚好 |
|------|------|
| "了解我们的用户" | "旅行预订时，用户的决策依据是什么？不同用户的决策路径有何差异？" |
| "用户体验怎么样" | "哪些用户在比价环节流失？他们卡在什么问题上？" |

### 3.2 设计访谈提纲

**结构：暖场 → 背景 → 核心行为 → 深挖动机 → 收尾**

```markdown
## 访谈提纲模板

### 暖场（5 min）
- 自我介绍 + 说明保密 + "没有对错答案"
- 简单聊几句对方的工作/生活（建立 Rapport）

### 背景（5 min）
- "先聊聊你的日常，在 [领域] 方面你一般怎么安排？"
- 目的：了解情境和习惯

### 核心行为探索（25-30 min）
- "你能带我走一遍上次 [做某事] 的完整过程吗？从最开始想做这件事，到最后完成。"
- 追问链：
  - "这一步你是怎么做的？"
  - "当时在想什么？"
  - "为什么选了这个方式？还考虑过别的吗？"
  - "这里有什么让你不顺畅/犹豫/纠结的地方？"

### 深挖动机（10 min）
- "在这件事上，你最在意的是什么？"
- "如果用一个词形容你对 [产品/服务] 的感受，会是什么？"
- "你觉得什么样的体验是'完美'的？"

### 收尾（5 min）
- "还有什么我没问到但你觉得重要的？"
- 感谢 + 后续联系方式
```

### 3.3 提纲设计原则

| 原则 | 做法 | 反面 |
|------|------|------|
| 开放式提问 | "跟我聊聊你上次…" | "你是不是觉得…" |
| 聚焦过去行为 | "你当时做了什么" | "你以后会怎么做" |
| 不含产品假设 | "你怎么解决这个问题" | "你觉得我们的XX功能好不好" |
| 有追问空间 | 主问题 70%，30% 留给即兴追问 | 念稿式 50 题 |
| 先 Pilot | 找 1 个人试一遍提纲 | 第一场正式访谈才发现提纲有问题 |

## 四、招募

### 4.1 招募标准（Screener）

基于你要研究的用户群体设定筛选条件：

```markdown
## 招募标准示例（旅行预订 App）

### 必须满足
- 过去 3 个月内有过线上预订旅行产品的行为
- 年龄 20-55
- 愿意进行 45-60 分钟远程/面对面交谈

### 差异化维度（确保样本多样性）
- 出行频率：低频（1-2 次/年） vs 高频（6+ 次/年）
- 决策风格：计划型 vs 即兴型
- 消费水平：经济型 vs 品质型
- 渠道偏好：App vs 小程序 vs PC

### 排除
- 旅游行业从业者
- 过去 3 个月参加过类似调研
```

### 4.2 样本量

| 经验法则 | 说明 |
|---------|------|
| 最少 8 人 | 低于 8 人难以发现行为模式 |
| 理想 12-15 人 | 大多数情况下可达到饱和 |
| 上限 25-30 人 | 再多收益递减 |
| 饱和判断 | 连续 2-3 场访谈没有新发现 → 可以停了 |

### 4.3 招募渠道

| 渠道 | 优点 | 缺点 |
|------|------|------|
| 产品内推送/弹窗 | 精准、真实用户 | 可能偏向活跃用户 |
| 客服推荐 | 多样性好 | 可能偏向有问题的用户 |
| 社群/微信群 | 快速 | 样本偏差 |
| 专业招募公司 | 样本质量可控 | 成本高 |
| 老用户数据库 | 效率高 | 需要事先积累 |

## 五、执行访谈

### 5.1 访谈中的关键技巧

**倾听比例**：研究者说话不超过 20%，用户说 80%。

**沉默的力量**：提问后至少等 5 秒。用户停顿不代表结束，往往是在组织更深层的想法。

**三层追问**：

```
L1 · 回声追问    → 重复对方的关键词（"你说的'纠结'是指？"）
L2 · 展开追问    → "能多说一点吗？""后来怎样了？"
L3 · 确认追问    → "我理解的是… 对吗？"
```

**避雷六条**：

| 禁止 | 替代 |
|------|------|
| 诱导性问题（"你是不是觉得太慢了"） | "你怎么看这个速度？" |
| 连续 Why-Why-Why | "发生了什么？""当时是什么情况？" |
| 一次问两个问题 | 拆开，一次只问一个 |
| 评价式反应（"很好！"） | 中性反应（"嗯，然后呢"） |
| 中途打断 | 等对方说完再追问 |
| 急于进入下一题 | 在有趣的点多停留 |

### 5.2 现场观察（Contextual Inquiry）

如果条件允许，在用户真实环境中观察（去他们的工位/家里/咖啡馆），效果远超会议室访谈：

| 原则 | 做法 |
|------|------|
| 在真实场景中 | 去用户平时做这件事的地方 |
| 伙伴关系 | "你做你的，我在旁边看，不懂就问" |
| 当场确认 | "我看到你刚才…是因为…对吗？" |
| 有焦点 | 不是漫无目的看一整天，而是聚焦特定任务 |

### 5.3 记录规范

| 维度 | 做法 |
|------|------|
| 录音/录屏 | 必须获得同意；用于回溯，不替代笔记 |
| 实时笔记 | 记关键引语 + 情绪标记 + 行为细节 |
| 笔记标记法 | [B]=行为 [P]=痛点 [G]=目标 [!]=意外 [Q]=待追问 |
| 表情/肢体 | 用户说"还好"但皱眉 → 记"语气犹豫" |

## 六、Field Debrief（每日复盘）

**这是防止数据烂在硬盘里的关键纪律。**

### 6.1 规则

| 要素 | 规范 |
|------|------|
| 时间 | 每天最后一场访谈结束后 30 分钟内 |
| 参与者 | 所有当天参与观察的人 |
| 时长 | 15-30 分钟 |
| 形式 | 每人轮流说：1 个最意外的发现 + 1 个印象最深的行为 + 1 个与之前受访者的对比 |

### 6.2 Topline Summary 模板

```markdown
## 受访者 #P03 — [代称]
**日期**: 2026-05-29 | **时长**: 50 min | **方式**: 远程 Zoom

### 核心行为模式
- [B] …

### 痛点
- [P] …

### 目标/动机
- [G] …

### 意外发现
- [!] …

### 初步 Persona 假设
- 接近哪个 Proto-Persona？在哪些维度上不一样？
```

## 七、分析（概要）

> 详细分析方法见 `core/05-analysis-clustering.md`

定性路径的分析核心是**从访谈数据中提取行为变量，然后按行为相似性分群**：

```
逐条访谈笔记 → 提取行为片段 → 标记行为变量维度 → 亲和图归类 → 发现行为模式 → 分群 → Persona
```

---

## 八、本章核心要点

1. **定性路径是大多数团队的最佳选择**——12-15 人访谈即可达到饱和
2. **提纲设计决定数据质量**——开放式 + 聚焦过去行为 + 不含产品假设
3. **招募要确保多样性**——在关键行为维度上确保差异
4. **倾听 80% + 三层追问**是访谈核心技巧
5. **每天做 Debrief**——防止数据堆积不消化
6. **让核心成员旁听 1-2 场**——一次真实访谈的说服力 > 100 页报告
