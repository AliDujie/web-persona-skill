# 04 — 混合路径：定性定量如何结合

---

## 一、为什么要混合

| 单纯定性的问题 | 单纯定量的问题 | 混合解决 |
|---|---|---|
| 不知道"这类人有多少" | 不知道"为什么数字是这样" | 先探索后验证 |
| 难以说服数据驱动的高管 | 产出冷冰冰的数字缺乏共情 | 既有严谨性又有血肉 |
| 样本可能有偏 | 问卷题目可能问错方向 | 定性确保方向对，定量确保结论准 |

**混合路径 = 信心最高的 Persona**。代价是时间和资源最多。

---

## 二、两种混合设计

### 2.1 序列式（最常见）

```
定性探索 → 定量验证 → 定性深化

Phase 1 · 定性探索（W1-3）
├── 8-12 场深度访谈
├── 发现行为模式 + 初步 Persona 假设
└── 产出：行为变量维度清单 + 3-5 个假设 Persona

Phase 2 · 定量验证（W4-7）
├── 基于 Phase 1 发现设计问卷
├── 300-500 份样本采集
├── 统计聚类验证/修正 Persona 假设
└── 产出：验证后 Persona + 市场占比

Phase 3 · 定性深化（W8-9）
├── 每个验证后的 Persona 抽 2-3 人深访
├── 补充故事、引语、情境细节
└── 产出：完整 Persona（有数字有故事）
```

### 2.2 并行式（适合时间紧）

```
定量挖掘 ─┐
           ├── 合并分析 → Persona 产出
定性访谈 ─┘

· 定量：利用已有行为数据（埋点/CRM）做初步聚类
· 定性：同时进行 8-10 场访谈
· 合并：统计分群 + 访谈发现交叉比对 → Persona
```

---

## 三、序列式详细操作

### Phase 1：定性探索

目标不是"做完 Persona"，而是**发现行为维度 + 形成假设**。

| 步骤 | 做法 | 产出 |
|------|------|------|
| 1. 访谈 8-12 人 | 按 `core/02-qualitative-research.md` 执行 | 访谈笔记 |
| 2. 提取行为变量 | 从访谈中总结"用户在哪些维度上有差异" | 行为变量清单（15-30 个维度） |
| 3. 初步聚类 | 定性判断哪些用户行为相似 | 3-5 个假设 Persona |
| 4. 设定问卷假设 | "如果假设成立，问卷应该能区分出X和Y" | 可验证假设列表 |

**关键产出：行为变量清单**

```markdown
## 行为变量清单示例（旅行预订 App）

### 决策行为
- 计划周期：提前 3 个月 vs 出发前 1 周
- 比价广度：只看 1 个平台 vs 比较 3+ 个
- 决策参与：独自决定 vs 与家人/朋友商量

### 使用行为
- 频率：月活 vs 季活 vs 年活
- 渠道偏好：App vs 小程序 vs PC
- 功能使用深度：仅预订 vs 攻略+预订+社区

### 动机/价值观
- 核心驱动：价格 vs 体验 vs 效率 vs 社交
- 风险态度：选主流大牌 vs 愿意尝试小众
- 品牌关系：多平台比较 vs 单平台忠诚
```

### Phase 2：定量验证

将 Phase 1 的行为变量转化为问卷题目，大样本验证：

| 步骤 | 做法 |
|------|------|
| 1. 维度→题目 | 每个行为维度设计 1-3 道量化题 |
| 2. Pilot | 20-30 人试答，检查理解和时长 |
| 3. 大规模采集 | 300-500 份 |
| 4. 聚类分析 | 按 `core/03-quantitative-research.md` 执行 |
| 5. 与定性假设对比 | 统计分群 ≈ 定性假设？偏差在哪？ |

**对比检验**：

```
定性假设          统计结果           判断
────────         ────────          ────────
假设有 5 类      统计最优 4 类      → 哪个假设类被合并了？为什么？
"价格敏感型"     确实独立成簇       → 假设确认 ✓
"品质追求型"     被拆成两个子簇     → 发现新区分维度，更新 Persona
"随性型"没出现   被吸收进其他簇     → 可能是少数群体，考虑降级
```

### Phase 3：定性深化

从每个统计验证后的 Persona 中抽取 2-3 个典型用户做深度访谈：

| 目标 | 做法 |
|------|------|
| 补充故事 | "带我走一遍你上次预订旅行的完整过程" |
| 获取引语 | 记录最能代表这个 Persona 的 1-2 句原话 |
| 理解情境 | 在什么场景下触发行为？有什么约束条件？ |
| 验证命名 | 和受访者聊"如果用一个词形容你的旅行风格？" |

## 四、关键衔接点

混合路径最容易出问题的地方是**阶段之间的衔接**：

### 4.1 定性 → 定量的翻译

| 定性发现 | 翻译为问卷题目 | 注意 |
|---------|-------------|------|
| "有些人会花大量时间做攻略" | "在决定旅行目的地前，你通常花多少时间做功课？" + 5 档量表 | 具体化、可量化 |
| "两类人对价格敏感度差异很大" | MaxDiff 题：排列决策因素优先级 | 用强制排序而非打分 |
| "有一类人几乎只用一个平台" | "过去 3 个月你使用了几个旅行预订平台？" | 行为事实而非态度 |

### 4.2 定量 → 定性深化的选人

| 步骤 | 做法 |
|------|------|
| 1. 从每个簇中选"典型"代表 | 离簇心最近的 3-5 人 |
| 2. 选"边界"案例 | 在两个簇之间的 1-2 人（帮助理解边界在哪） |
| 3. 在问卷末尾留联系方式 | "愿意参加 30 分钟深度交流？" |

## 五、时间与资源规划

### 5.1 完整时间线

```
W1-2 ·── Phase 1 定性探索
        ├── W1: 招募 + 访谈准备 + 前 4 场访谈
        └── W2: 后 4-8 场访谈 + 即时分析

W3   ·── 过渡
        ├── 行为变量总结
        ├── 问卷设计 + Pilot
        └── 招募大样本

W4-5 ·── Phase 2 定量验证
        ├── W4: 问卷采集
        └── W5: 聚类分析 + 与定性假设对比

W6   ·── Phase 3 定性深化
        ├── 每个 Persona 2-3 场深访
        └── 叙事化撰写

(可选) W7 ·── 应用工作坊
```

### 5.2 最低配置团队

| 角色 | 职责 | 投入 |
|------|------|------|
| 研究员/设计师 | 全流程主导 | 全程 |
| 数据分析师 | 问卷分析 + 聚类 | Phase 2（约 1 周） |
| 产品经理 | 旁听访谈 + 参与分析工作坊 | 关键节点 |
| 运营/市场 | 提供用户招募渠道 | Phase 1-2 |

## 六、混合路径常见错误

| # | 错误 | 后果 | 预防 |
|---|------|------|------|
| 1 | 定性和定量各做各的 | 两套结果对不上 | 定性产出要直接转化为问卷输入 |
| 2 | Phase 1 做太深 | 陷入定性分析不愿进入定量 | 控制在 2 周内，目标是"发现维度"不是"出 Persona" |
| 3 | 问卷没有基于定性发现设计 | 浪费了混合路径的核心优势 | 逐条追溯：每道题对应哪个定性发现？ |
| 4 | 统计和定性矛盾时只信统计 | 错过统计看不到的情境因素 | 矛盾处做追加访谈理解原因 |
| 5 | 跳过 Phase 3 | Persona 有数字没有人味儿 | 至少每个 Persona 补 2 场深访 |

---

## 七、本章核心要点

1. **混合路径 = 信心最高**——既有"为什么"又有"有多少"
2. **序列式是标准做法**——定性探索 → 定量验证 → 定性深化
3. **定性 → 定量的翻译是关键**——每道问卷题必须追溯到定性发现
4. **统计和定性矛盾时不要慌**——矛盾处往往藏着最有价值的发现
5. **6-9 周是合理时间**——比纯定性多 3-4 周，但信心大幅提升
