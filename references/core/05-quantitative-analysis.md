# T5 · 定量分析 — 执行协议

## 触发条件
用户提供了 CSV / Excel / 数据表格，或说"帮我分析这些数据做分群"。

## 输入
- 数据文件（必须）：CSV / Excel / 或贴出的表格数据
- 哪些列是行为变量、哪些是人口统计（可选——不给就自动判断）

## 执行步骤

### Step 1：数据探索

拿到数据后立即做：
1. 读取前 5 行，展示给用户确认
2. 统计每列的类型（数值/分类）、缺失率、唯一值数
3. 自动判断哪些是行为变量（用于聚类输入）、哪些是描述变量

如果无法判断，问一句：
> "这些列里，哪些描述的是用户**做了什么/怎么做的**（行为），哪些是**年龄/性别这类背景信息**？"

### Step 2：数据清洗

```python
# 执行清洗
# 1. 删除完成时间异常短的样本（如有时间列）
# 2. 删除直线作答（连续N题相同答案）
# 3. 处理缺失值：缺失 > 30% 的样本删除，剩余用中位数填充
# 4. 数值变量标准化（Z-score）
# 5. 分类变量编码
```

向用户报告：
> "原始 [N] 条数据，清洗后剩余 [M] 条（删除 [K] 条，原因：[...]）。"

### Step 3：聚类分析

```python
from persona.clustering import PersonaClusterer

# 自动选择方法 + 寻找最优 K
clusterer = PersonaClusterer(method="auto")
result = clusterer.fit(df_clean[behavior_columns], n_clusters_range=(3, 7))
```

如果 clustering.py 可用，直接调用。如果不可用（sklearn 未安装），用以下逻辑手动执行：
1. 对 K=3,4,5,6,7 分别跑 KMeans
2. 计算轮廓系数（>0.25 可接受，>0.5 好）
3. 画肘部图（SSE vs K）
4. 选择最优 K = 统计最优 与 业务可解释性 的平衡点

**早停规则**（借鉴 deep-research-iterative `<done>` 信号）：
- 如果连续两个 K 的轮廓系数变化 < 0.02 且业务可解释性相同 → 提前停止扫描
- 如果某 K 的轮廓系数 > 0.5 且簇大小均衡（最大/最小簇 < 5x）→ 直接选用，不再向上探索
- 如果所有候选 K 的轮廓系数都 < 0.20 → 报告"数据无明显聚类结构"，建议增加行为变量或考虑换 LCA 方法

**Fallback 路径**（无 sklearn 环境）：
- 对 N ≤ 30 的样本，用 LLM 直接做行为模式归纳分群
- 产出明确标注："由于环境无 sklearn，使用 LLM 启发式分群（非统计聚类），不输出轮廓系数"

### Step 4：解读结果

对每个簇，分析：
- 各行为变量的簇中心（均值）
- 与总体均值的偏差
- 最能区分该簇的 Top 3 变量
- 簇大小（占比）

## Pitfalls

| 症状 | 修复 |
|------|------|
| K 值扫描全跑一遍才决定 → 浪费算力 | 启用早停规则（轮廓 > 0.5 + 簇均衡直接选用） |
| 数据没标准化直接跑 KMeans → 大量级变量主导聚类 | Step 2 强制 Z-score 标准化数值变量 |
| 聚类结果不做 bootstrap → 无法判断稳定性 | clustering.py 默认 bootstrap_n=20，不要关 |
| 直接把人口统计变量塞进聚类 → 行为聚类被人口统计稀释 | Step 1 严格区分行为变量 vs 描述变量，仅前者入聚类 |
| 决策树准确率 < 70% 还输出规则 → 误导产品经理 | Verification 强制 CV 准确率 ≥ 70%，否则只输出"规则不可靠"提示 |
| 沙箱无 sklearn 直接报错退出 | 走 Fallback 路径用 LLM 启发式分群并明确标注 |
