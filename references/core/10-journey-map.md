# T10 · 旅程地图 — 执行协议

## 触发条件
- 用户说"帮我做旅程地图" / "帮我做 Journey Map" / "用户体验地图"
- T6 完成后用户选择了旅程地图
- 用户有 Persona + 使用场景

## 输入
- Persona 文档（必须）
- 使用场景（必须——如 T6 已生成则沿用）
- 已知触点列表（可选——如有则更精确）

## 执行步骤

### Step 1：确认地图范围

如果用户没明确，问一句：
> "要画哪段旅程？比如：从知道产品到首次下单的全程 / 只画某个具体任务流程 / 从购买到复购的完整生命周期。"

### Step 2：为每个 Primary/Secondary Persona 生成 Journey Map

**基于 T6 产出的使用场景，扩展为完整 Journey Map。**

Journey Map 比场景多三样东西：
1. **情绪曲线**——每个阶段用户的情绪高低
2. **触点清单**——TA 在每个阶段接触产品的具体界面/渠道
3. **后台支撑**——前台体验背后需要什么系统/服务/人力支撑

## 产出模板

```markdown
## Journey Map：[Persona 名字] × [场景名称]

### 旅程概览

**Persona**：[行为标签·名字]
**核心目标**：[TA 整个旅程的最终目标]
**旅程范围**：从 [起点] 到 [终点]
**总时长**：[典型时长]

---

### 阶段拆解

#### 阶段 1：[触发/意识]

| 维度 | 内容 |
|------|------|
| **用户在做什么** | [具体行为——如"在朋友圈看到别人旅行照片"] |
| **用户在想什么** | [内心想法——如"好羡慕，我也该休假了"] |
| **用户感受** | [情绪状态] 😐 → 🙂 (3/5) |
| **触点** | [接触的渠道/界面——如"朋友圈/小红书/同事聊天"] |
| **痛点** | [这个阶段的卡点——如"不知道去哪/预算不确定"] |
| **机会** | [产品可做什么——如"推送个性化目的地推荐"] |

---

#### 阶段 2：[探索/研究]

| 维度 | 内容 |
|------|------|
| **用户在做什么** | [如"搜索目的地/看攻略/问朋友"] |
| **用户在想什么** | [如"去哪便宜又好玩？能请几天假？"] |
| **用户感受** | 🙂 → 😟 (2/5) [信息过载开始焦虑] |
| **触点** | [App 首页/搜索/攻略频道/竞品 App] |
| **痛点** | [信息太多反而选不出来/不确定哪个信息可信] |
| **机会** | [基于 Persona 偏好做信息筛选/给出决策简化工具] |

---

#### 阶段 3：[决策/预订]

| 维度 | 内容 |
|------|------|
| **用户在做什么** | [如"比价/选日期/看评价/下单"] |
| **用户在想什么** | [如"这个价格会不会明天降？取消要收费吗？"] |
| **用户感受** | 😟 → 🙂 → 😊 (4/5) [下单后短暂满足] |
| **触点** | [搜索结果页/详情页/支付页/确认页] |
| **痛点** | [比价耗时/担心买贵/取消政策不清晰] |
| **机会** | [价格保护/一键比价/取消政策前置] |
```
