# T1 · 立项规划 — 执行协议

## 触发条件
用户说"帮我做 Persona"、"我需要用户画像"、或描述了产品/业务背景希望做用户研究。

## 输入
- 产品/业务描述（必须）
- 团队规模和可投入时间（可选，不给就问）
- 已有用户数据情况（可选）

## 执行步骤

### Step 1：收集必要信息

只问以下问题（缺哪个问哪个）：
1. 你的产品/业务是什么？服务什么场景？
2. 团队大约几个人？有多少时间投入（1周/2周/1个月）？
3. 已有哪些用户数据？（没有也没关系）

### Step 2：现有数据审计

**在决定做什么研究之前，先挖掘已有的东西。**

对用户说有的每种数据源，执行以下提取：

| 数据源 | 提取什么 | 产出 |
|--------|---------|------|
| 产品埋点/分析后台 | 用户分布、频率分布、路径差异、留存差异 | 初步行为分群假设 |
| 客服/工单记录 | 高频问题分类、不同类型用户的诉求差异 | 痛点清单 + 潜在分群线索 |
| CRM/用户数据库 | 用户属性分布、生命周期价值差异、活跃度分层 | 量化分层初稿 |
| 用户评价/反馈 | 情感分析、高频关键词、正负面主题 | 动机/态度维度假设 |
| 历史调研报告 | 过去的发现、已知的用户类型 | 验证/更新/推翻旧结论 |
| 竞品公开信息 | 竞品如何分类用户、服务差异化方向 | 市场视角的分群维度 |

**审计产出**：

```markdown
## 现有数据审计结果

### 已有数据盘点
| 数据源 | 有/无 | 质量 | 关键发现 |
|--------|-------|------|---------|
| [数据源1] | ✅ | [好/一般/差] | [一句话发现] |
| [数据源2] | ❌ | - | - |

### 初步假设
基于现有数据，初步猜测存在以下 N 类用户：
- 假设群 A：[行为特征描述]，依据：[哪个数据源支撑]
- 假设群 B：[...]
- 假设群 C：[...]

### 数据缺口
- 已知用户"做了什么"，但不知道"为什么"→ 需要定性访谈补充动机
- 已知行为分布，但不确定"该分几群"→ 需要统计聚类验证
- 完全没有数据 → 需要从头采集

### 建议研究方向
基于审计结果，最高效的下一步是：[具体建议]
```

### Step 3：评估 & 推荐方法

根据审计结果 + 用户回答，在以下路径中选择：

```
条件 A：已有访谈稿/用户反馈文本
→ 直接进 T3（定性分析）

条件 B：已有问卷/埋点/CRM 数据
→ 直接进 T5（定量分析）

条件 C：两者都有
→ T3 → T5 → T6（混合路径）

条件 D：什么数据都没有 + 时间 < 2周
→ T2（设计访谈）→ 执行 5-8 场 → T3 → T6

条件 E：什么数据都没有 + 时间 ≥ 4周
→ T2（设计访谈）→ T4（设计问卷）→ T3+T5 → T6

条件 F：什么数据都没有 + 时间极短（< 1周）
→ 直接做 Proto-Persona 工作坊 → 输出假设性 Persona（标注"未验证"）
```

### Step 4：输出项目计划

## 产出模板

```markdown
## Persona 项目计划

### 推荐方法：[定性/定量/混合/Proto-Persona]
**理由**：[一句话说明为什么选这个方法]

### 现有数据利用
- [哪些已有数据会作为输入]
- [初步假设是什么——后续研究验证/推翻它]

### 时间线
| 阶段 | 内容 | 时长 | 产出 |
|------|------|------|------|
| W1 | [具体行动] | X天 | [具体交付物] |
| W2 | [...] | X天 | [...] |
| ... | | | |

### 我现在能帮你做的
- [ ] [下一步具体 action——比如"分析你的埋点数据"或"设计访谈提纲"]

### 需要你准备的
- [如果有的话——比如"导出最近3个月的用户行为数据"]
```

## 自动衔接
- 如果推荐 T2（访谈设计），询问"要我现在就帮你出访谈提纲吗？"
- 如果用户已提供数据，直接进入 T3 或 T5，不再走 T1
- 审计发现有现成数据可分析 → 直接进对应任务
