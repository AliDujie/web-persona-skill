# 01 — 立项规划：为什么建、选什么方法、组什么团队

---

## 一、先回答一个问题：你现在该不该建 Persona？

不是所有项目都需要 Persona。在投入资源之前，先用这三个判据做决策：

| 判据 | 该建 | 不该建 |
|------|------|--------|
| 用户差异 | 用户群体间行为/目标差异大 | 用户高度同质（如内部工具只有一种角色） |
| 决策需要 | 团队频繁争论"用户到底要什么" | 已有清晰共识且产品成熟 |
| 项目阶段 | 新产品/新市场/重大改版/用户增长瓶颈 | 短期运营活动/纯技术重构 |

如果三个判据中有两个指向"该建"，就值得投入。

---

## 二、三种方法路径：选哪个？

Persona 的搭建方法分三大类，各有适用场景。**选择方法比选择工具更重要——方向错了，执行再精也白搭。**

### 2.1 三种方法总览

| 维度 | 定性路径 | 定量路径 | 混合路径 |
|------|---------|---------|---------|
| 核心手段 | 深度访谈 + 现场观察 | 大样本问卷 + 统计聚类 | 定性探索 → 定量验证 |
| 所需样本 | 8-30 人 | 200-1000+ 人 | 定性 8-15 + 定量 300+ |
| 所需时间 | 3-6 周 | 4-8 周 | 6-12 周 |
| 所需技能 | 访谈技巧 + 定性编码 | 问卷设计 + 统计分析 | 两者都要 |
| 产出特点 | 深刻（理解动机/情境） | 精确（可量化市场份额） | 深刻且精确 |
| 适合场景 | 大多数团队的默认选择 | 大组织/需向高管证明/细分市场规模 | 资源充足 + 高决策权重场景 |
| 成本 | 中 | 高 | 最高 |

### 2.2 如何选择

```
你的情况是？

├── 团队小（<10人）/ 预算有限 / 时间紧（<4周）
│   └─► 定性路径（最高性价比，大多数团队的正确选择）
│
├── 组织大 / 需要说服高管 / 需要知道"每类用户占多少比例"
│   └─► 定量路径（统计严谨性是说服力的来源）
│
├── 产品复杂 + 决策权重高 + 资源充足
│   └─► 混合路径（先定性探方向，再定量验规模）
│
└── 项目启动期 / 还没有任何用户认知
    └─► 先做 Proto-Persona 工作坊（2-4h），再决定是否投入正式研究
```

### 2.3 Proto-Persona：最低成本的起步

如果你连"用户是谁"都完全没概念，或者项目刚启动需要快速对齐团队假设，可以先做一轮 Proto-Persona（假设型 Persona）：

| 要素 | 规范 |
|------|------|
| 时间 | 2-4 小时工作坊 |
| 参与者 | 项目核心成员 5-8 人 |
| 方法 | 每人独立写 2-3 个"我认为的典型用户"→ 合并相似 → 讨论差异 → 形成 3-5 个假设画像 |
| 输出 | 每个 Proto-Persona 一张卡：名字 + 一句话描述 + 核心目标 + 痛点 + 行为特征 |
| 本质 | 让团队的**隐性假设**变成**显性共识**，后续研究去验证/推翻它 |
| 注意 | Proto-Persona 是起点不是终点——必须用真实数据验证 |

## 三、核心原则：全员参与

**这是做 Persona 最容易被忽视、也是最影响成败的一件事。**

### 3.1 为什么必须全员参与？

| 只有研究员做 | 核心成员参与 |
|---|---|
| Persona 做完 → 交付文档 → 束之高阁 | Persona 共建 → 全员理解 → 融入决策 |
| 团队不理解"为什么是这几个人" | 团队亲身参与分析，对 Persona 有"所有权" |
| 推广时需要反复说服 | 不需要推广——他们本来就在 |
| 容易被挑战"你怎么知道" | 大家共同见证了数据→结论的过程 |

### 3.2 "核心成员"包括谁？

| 角色 | 为什么必须在 | 参与哪些环节 |
|------|------------|------------|
| 产品经理/负责人 | 最终决策者，Persona 要影响他的判断 | 全程 |
| 设计师 | 直接使用 Persona 做设计决策 | 全程 |
| 技术负责人 | 理解用户才能做技术取舍 | 关键节点（分析工作坊/验证） |
| 市场/运营 | 用户触达最多、拥有一手反馈 | 数据提供 + 验证环节 |
| 客服/销售 | 直接对话用户、积累大量直觉 | 访谈阶段（提供线索/参与观察） |
| 数据分析师 | 定量路径的技术保障 | 定量采集 + 聚类分析 |

### 3.3 参与方式设计

不是让所有人从头到尾全程跟——而是**在关键节点拉进来**：

```
阶段 1 · 立项          → 全体：确认目标、选方法、分工
阶段 2 · 数据采集       → 研究员主导 + 其他人轮流观察 1-2 场访谈
阶段 3 · 分析工作坊     → 全体：一起做亲和图 / 看聚类结果
阶段 4 · Persona 塑造   → 核心 3-4 人协作撰写
阶段 5 · 验证           → 全体：各自从自己视角审视合理性
阶段 6 · 应用推广       → 全体：各自领域如何用这些 Persona
```

### 3.4 "观察访谈"的具体操作

让非研究员参与最高效的方式是**让他们观察 1-2 场真实访谈**：

| 步骤 | 做法 |
|------|------|
| 选 1-2 场 | 挑选代表性强的受访者（如差异最大的两类用户各一场） |
| 旁听规则 | 不插话、不表态、只记笔记 |
| 即时 Debrief | 访谈结束后 10 分钟：每人说 1 个"最意外的发现" |
| 效果 | 一次真实访谈的说服力 > 100 页报告 |

## 四、项目规划清单

### 4.1 启动前必须明确的 7 件事

| # | 问题 | 示例答案 |
|---|------|---------|
| 1 | 为什么做 Persona？解决什么决策问题？ | "我们不知道新功能该优先服务哪类用户" |
| 2 | 选哪种方法？（定性/定量/混合） | "定性路径，因为我们团队 8 人、预算有限" |
| 3 | 覆盖范围？（哪些用户群/产品线） | "旅行预订 App 的 C 端用户" |
| 4 | 项目核心成员是谁？ | "PM + 主设计师 + 技术 Lead + 运营" |
| 5 | 时间表？关键里程碑？ | "3 周完成：W1 采集 / W2 分析 / W3 产出" |
| 6 | 预期产出几个 Persona？ | "3-5 个（不超过 7，否则团队记不住）" |
| 7 | Persona 将用在哪些场景？ | "功能优先级排序 + 设计评审 + 营销分层" |

### 4.2 Persona 数量的经验法则

| 产品类型 | 建议数量 | 理由 |
|---------|---------|------|
| 单一功能工具（如天气 App） | 2-3 | 用户差异小 |
| 综合平台（如旅行 App） | 3-5 | 行为分化明显 |
| B2B SaaS | 3-4（按角色） + 1 买家 | 使用者和决策者不同 |
| 双边平台 | 每边 2-3 | 供给侧和需求侧分别做 |

**黄金法则**：宁少不多。5 个用好 > 10 个没人记住。

### 4.3 时间线模板

**定性路径（最常见）— 3-4 周：**

```
W1 ·── 规划 + 招募 + 访谈准备
       ├── Day 1-2: 项目启动会（全员参与）
       ├── Day 3-4: 访谈提纲设计 + Pilot 测试
       └── Day 5: 招募启动（同步进行）

W2 ·── 数据采集
       ├── 8-12 场深度访谈（每天 2-3 场）
       ├── 核心成员旁听 1-2 场
       └── 每天结束 Field Debrief

W3 ·── 分析 + 产出
       ├── Day 1-2: 分析工作坊（全员参与）
       ├── Day 3-4: Persona 撰写
       └── Day 5: 验证 + 发布

(可选) W4 ·── 应用工作坊
       └── 各岗位讨论"这些 Persona 对我的工作意味着什么"
```

## 五、立项常见错误

| # | 错误 | 后果 | 预防 |
|---|------|------|------|
| 1 | 没有明确的决策问题 | 做完不知道用来干嘛 | 必须能填完"做 Persona 是为了解决___" |
| 2 | 只有研究员参与 | 成果束之高阁 | 从 Day 1 拉核心成员进来 |
| 3 | 贪多求全 | 10 个 Persona 都很浅 | 控制在 3-5 个，深 > 多 |
| 4 | 选错方法 | 小团队做定量→资源耗尽；大组织做纯定性→缺说服力 | 按 §2.2 决策树选择 |
| 5 | 没有时间表 | 项目漫延、永远不结束 | 必须有固定 Deadline |
| 6 | 把 Persona 当文档而非工具 | 做完就完了 | 立项时就规划"做完后怎么用" |

---

## 六、本章核心要点

1. **先判断该不该做**——不是所有项目都需要 Persona
2. **选方法比选工具重要**——定性/定量/混合三条路，按团队规模和决策需要选
3. **全员参与是成败关键**——不是全程跟，是在关键节点把核心成员拉进来
4. **3-5 个就够**——宁少不多，深度 > 数量
5. **Proto-Persona 是安全起步**——不确定时先花 2 小时对齐假设
6. **从 Day 1 就规划"做完后怎么用"**——目的驱动全过程
