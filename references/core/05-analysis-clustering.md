# 05 — 分析：从原始数据到行为分群

---

## 一、本章位置

```
数据采集完成 → 【本章：分析与聚类】→ Persona 塑造
```

无论你走的是定性路径、定量路径还是混合路径，都需要经过"分析"这一步——把原始数据转化为有意义的用户分群。

---

## 二、定性分析路径

### 2.1 全流程

```
逐条整理笔记 → 提取行为片段 → 识别行为变量 → 亲和图归类 → 发现模式 → 形成分群
```

### 2.2 Step 1：整理原始数据

将访谈笔记拆成**独立的行为/态度/动机片段**，每个片段写在一张"卡片"上：

```markdown
## 卡片示例

[P03-行为] 每次预订前至少比较 3 个平台的价格
[P03-动机] "同样的酒店差价可能有 200 块，不比怎么行"
[P03-痛点] 比价费时间，希望有人帮他做好
[P05-行为] 从不比价，朋友推荐什么平台就用什么
[P05-动机] "花那个时间不如多玩一个地方"
[P05-态度] 对价格差异不敏感，更在意"省事"
```

### 2.3 Step 2：识别行为变量维度

从所有卡片中提炼"用户在哪些维度上表现出差异"：

| 行为变量 | 极端A | 极端B |
|---------|-------|-------|
| 计划程度 | 提前数月详细规划 | 出发前一天才订 |
| 比价投入 | 多平台反复比较 | 选定品牌不再看别的 |
| 决策驱动 | 价格优先 | 体验优先 |
| 信息来源 | 自己研究攻略 | 依赖朋友/KOL 推荐 |
| 出行同伴 | 独自出行 | 家庭/团体 |
| 使用深度 | 仅用预订功能 | 攻略+社区+预订全用 |

### 2.4 Step 3：亲和图工作坊

**这是全员参与的关键环节。**

| 要素 | 规范 |
|------|------|
| 参与者 | 核心团队 4-8 人 |
| 时长 | 2-4 小时 |
| 工具 | 便利贴（线下）或 Miro/FigJam（远程） |
| 规则 | 默读 → 独立分组 → 讨论合并 → 命名 |

**操作步骤**：

```
1. 准备
   · 将所有行为片段打印成卡片（或写在便利贴上）
   · 每人分到一份完整卡片集

2. 独立分组（20-30 min，静默操作）
   · 每人独立将卡片按"这些人的行为像"分组
   · 不交流、不讨论

3. 合并讨论（60-90 min）
   · 一人展示自己的分组逻辑
   · 其他人提出"我看到的不同"
   · 讨论差异 → 逐渐收敛

4. 命名（20 min）
   · 每组卡片用一句话描述"这是怎样的用户"
   · 不是取名字——是描述行为模式

5. 确认分群
   · 最终 3-5 个组 = 3-5 个潜在 Persona
```

### 2.5 Step 4：交叉验证

将每位受访者"放入"你发现的分群中，检查：

| 检查点 | 好的信号 | 坏的信号 |
|--------|---------|---------|
| 每个人都能放入某一群 | 10/12 的受访者清晰归入 | 多人"横跨两群"难以归类 |
| 每群有多人 | 每群至少 2-3 人 | 某群只有 1 人（可能是异常值） |
| 群间差异明显 | 用 2-3 个变量就能区分 | 需要 8 个变量才能勉强分开 |
| 群内一致性 | 同群的人行为高度相似 | 同群内部也差异很大 |

## 三、定量分析路径

### 3.1 数据预处理

| 步骤 | 做法 | 工具 |
|------|------|------|
| 编码 | 分类变量→数字编码 | pandas |
| 标准化 | 连续变量 Z-score 标准化 | sklearn.preprocessing |
| 缺失值 | 中位数/众数填充 或 删除 | 视缺失比例决定 |
| 降维（可选） | 变量 > 20 时先做因子分析 | sklearn.decomposition |

### 3.2 聚类执行

```python
# 简化示例（详细实现见 persona/clustering.py）
from persona.clustering import PersonaClusterer

clusterer = PersonaClusterer(method="auto")  # auto 会根据数据类型选择方法
result = clusterer.fit(df, n_clusters_range=(3, 7))

print(f"最优 K = {result.optimal_k}")
print(f"轮廓系数 = {result.silhouette_score:.3f}")
print(f"稳定性 = {result.stability:.1%}")

# 查看每个簇的特征
for cluster in result.cluster_profiles:
    print(f"\n--- 第 {cluster.id} 类（{cluster.size_pct:.0%}）---")
    print(cluster.top_features)
```

### 3.3 结果解读

| 产出 | 含义 | 下一步 |
|------|------|--------|
| 簇标签 | 每个样本属于哪一群 | 分析群间差异 |
| 簇中心 | 每群各变量的平均值 | 画雷达图对比 |
| 特征重要性 | 哪些变量最能区分各群 | 确定 Persona 的核心标签 |
| 占比 | 每群占总样本的比例 | 评估市场规模 |

## 四、行为变量详解

行为变量是分析的核心——选对变量，分群自然有意义；选错变量，再好的算法也没用。

### 4.1 Cooper 行为变量框架

Alan Cooper 提出的经典框架，将行为变量分为四类：

| 类型 | 含义 | 示例 |
|------|------|------|
| Activities（活动） | 用户做什么 | 使用频率、渠道选择、功能使用 |
| Attitudes（态度） | 用户怎么想 | 对技术的态度、风险偏好、品牌态度 |
| Aptitudes（能力） | 用户能力水平 | 技术熟练度、领域专业度 |
| Motivations（动机） | 用户为什么做 | 核心目标、深层需求 |

### 4.2 变量选择原则

| 原则 | 说明 | 反面 |
|------|------|------|
| 行为 > 人口统计 | 用"做什么"分群，不用"是谁"分群 | 按年龄/性别/城市分 |
| 可观察 > 自我报告 | 尽量用行为数据而非主观评分 | 只用态度量表 |
| 与业务决策相关 | 这个维度的差异会影响产品决策 | 有趣但无法指导行动 |
| 有足够变异性 | 受访者在这个维度上确实不同 | 人人都一样的维度 |
| 彼此独立 | 不要选高度相关的变量 | "比价次数"和"使用平台数"重复 |

### 4.3 维度数量

| 场景 | 建议维度数 | 理由 |
|------|-----------|------|
| 定性路径 | 6-12 个 | 太多则工作坊难以操作 |
| 定量路径 | 15-30 个 | 统计方法可处理更多维度 |
| 聚类输入 | 选最关键的 8-15 个 | 太多会增加噪声 |

## 五、从分群到 Persona 的过渡

分析结束后，你手里有"3-5 个行为上相似的用户群"。但这还不是 Persona——需要经过"塑造"才能变成有名字、有故事、有画面感的人物。

### 5.1 分析产出物清单

在进入下一步（`core/06-persona-creation.md`）之前，确保你有：

| 必须有 | 说明 |
|--------|------|
| 分群数量和大小 | 3-5 个群，各群的占比 |
| 每群的核心行为特征 | 2-3 个最能代表这群人的行为 |
| 群间的关键差异 | 什么维度最能区分不同群？ |
| 每群的典型受访者 | 定性路径：2-3 个真实案例；定量路径：簇心附近的样本 |
| 团队共识 | 核心成员参与了分析过程，认同这个分群方案 |

## 六、分析工作坊的具体操作

### 6.1 全员参与的分析会

| 要素 | 规范 |
|------|------|
| 时间 | 半天（3-4 小时） |
| 参与 | 核心团队全员 |
| 准备 | 研究员提前将访谈摘要/数据可视化准备好 |

### 6.2 议程

```
09:00 - 09:30  研究员呈现：原始数据摘要（不给结论）
09:30 - 10:30  全员操作：亲和图（定性）/ 看聚类结果（定量）
10:30 - 10:45  休息
10:45 - 11:30  讨论：分群方案 + 挑战 + 修正
11:30 - 12:00  达成共识：确认 N 个 Persona 的核心轮廓
12:00 - 12:30  下一步：分工撰写 Persona
```

### 6.3 促进技巧

| 场景 | 做法 |
|------|------|
| 有人想按人口统计分 | "如果不看年龄，这两组人的行为有什么不同？" |
| 讨论陷入僵局 | "我们先各退一步——如果只能选 3 个最重要的维度，你选哪 3 个？" |
| 某人声音太大 | 先独立思考写下来，再轮流发言 |
| 分群方案争议 | "我们能不能先试两种方案，看哪个对产品决策更有帮助？" |

## 七、本章核心要点

1. **行为变量是分析的核心**——选对维度比选对算法重要
2. **亲和图工作坊要全员参与**——这是建立"所有权"的关键步骤
3. **定性分析靠"模式识别"**——从个体片段中发现群体规律
4. **定量分析靠"统计验证"**——用算法确认分群的稳健性
5. **分析产出是"群画像"**——还不是 Persona，需要下一步塑造
