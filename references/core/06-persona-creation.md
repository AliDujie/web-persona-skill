# 06 — 角色塑造：从分群到活生生的人物

---

## 一、分群不是 Persona

分析完成后你有了"3-5 个行为相似的用户群"——但这只是原料。Persona 是**让整个团队记住、共情、并据此做决策的人物**。

| 分群报告 | Persona |
|---------|---------|
| "第 2 类用户：高频、价格敏感、多平台比较" | "精算旅行家 · 李薇：在出发前一周内刷遍 5 个平台，不找到最低价绝不下单。她说：'同样的酒店差 200 块，不比怎么行？'" |
| 给大脑看的 | 给心看的 |
| 分析师能理解 | 全团队（包括开发、运营、老板）都能记住 |

---

## 二、Persona 文档结构

### 2.1 标准结构（一个 Persona 占一页）

```markdown
## [名字]：[一句话描述]

### 照片 + 基本信息
- 年龄 / 职业 / 城市 / 家庭状况
- （注意：这些是"外衣"，帮助具象化，不是核心）

### 核心引语
> "一句能代表这个人的原话"

### 目标（Goals）
- 核心目标 1（最重要的）
- 核心目标 2
- 潜在目标（他们可能自己都没意识到的）

### 行为模式
- 关键行为 1
- 关键行为 2
- 关键行为 3

### 痛点与挫败
- 主要挫败感 1
- 主要挫败感 2

### 情境（Context）
- 在什么场景下触发行为
- 受什么外部条件影响

### 对产品的启示
- 这个 Persona 意味着我们应该... 
- 这个 Persona 不需要...

### 市场占比（如有定量数据）
- 占目标用户约 X%
```

### 2.2 精简版（适合快速对齐）

如果完整版太重，可以用"卡片版"——一个 Persona 就是一张名片大小的信息：

```
┌─────────────────────────────────────────┐
│  精算旅行家 · 李薇                        │
│  "同样的酒店差 200 块，不比怎么行？"       │
│                                          │
│  核心目标：用最少钱获得最满意的体验         │
│  关键行为：提前比价、多平台比较、关注促销    │
│  痛点：比价费时间、怕买贵了后悔            │
│  机会：帮她自动比价、提供"最低价保证"       │
│                                          │
│  占比：23%                                │
└─────────────────────────────────────────┘
```

## 三、叙事技巧：让 Persona 活起来

### 3.1 为什么叙事重要

数据告诉你"是什么"，叙事告诉团队"为什么应该在意"。一个好的 Persona 叙事能让开发者在写代码时想到"李薇会觉得这里太慢了"。

### 3.2 叙事的核心：一天 / 一个场景

不要写传记——写一个**具体场景下的完整行为序列**：

```markdown
## 李薇的一个典型预订场景

周五下午 3 点，李薇在工位上收到闺蜜群里的消息："下周末去杭州不？"
她立刻打开手机。第一反应不是搜景点——而是打开三个旅行 App 的酒店页面，
同一家酒店在飞猪、携程、美团分别报价多少。

她在两个 App 之间来回切换，截图对比。她特别看"优惠券能不能叠加"和
"取消政策是什么"。10 分钟后她发了一条消息到群里："飞猪这家便宜 40，
但只能预付不能退。你们觉得值不值？"

闺蜜回了一个"随你"。李薇有点纠结：如果下周临时加班呢？但 40 块的差价
让她最终选择了预付。下单后她截图存好——如果降价了她要找客服补差价。
```

### 3.3 叙事写作六原则

| 原则 | 做法 | 反面 |
|------|------|------|
| 具体 > 抽象 | "周五下午 3 点打开三个 App" | "她经常比较价格" |
| 场景 > 特质 | 描述在什么情境下做了什么 | 列出一堆性格标签 |
| 动作 > 想法 | "截图对比""来回切换" | "她是一个精打细算的人" |
| 矛盾 > 完美 | "纠结：40 块差价 vs 退订风险" | "她总是理性决策" |
| 原话 > 转述 | "同样的酒店差 200 块，不比怎么行" | "她认为比价很重要" |
| 一个场景 > 生平总结 | 聚焦一次具体的预订过程 | 从出生写到现在 |

### 3.4 引语的获取和使用

好的引语是 Persona 的灵魂——一句话就能让人记住这个角色：

| 好引语 | 为什么好 |
|--------|---------|
| "我不怕花钱，我怕花冤枉钱" | 简洁、有张力、直接揭示动机 |
| "攻略看太多反而不知道选哪个了" | 暴露真实痛点、有画面感 |
| "朋友推荐的我闭眼订" | 一句话区分出"信任型"用户 |

**获取方式**：在访谈中留意用户说的"金句"——通常是最生动、最有画面感的那句话。记在笔记里时加 `[★]` 标记。

## 四、命名的艺术

### 4.1 命名原则

| 原则 | 说明 | 示例 |
|------|------|------|
| 行为标签 + 人名 | 标签帮助理解，名字增加亲切感 | "精算旅行家 · 李薇" |
| 中性、不带评判 | 不暗示好坏高低 | ✗ "小白用户" ✗ "懒人" |
| 可记忆 | 2-4 个字的标签 | ✗ "高频使用多平台价格敏感计划型用户" |
| 彼此可区分 | 光听名字就知道不一样 | ✗ "旅行者A/B/C" |

### 4.2 命名方法

```
Step 1：从核心行为提炼 2-3 个关键词
        · "多平台比价" → 精算
        · "朋友推荐即下单" → 信任
        · "追求独特体验" → 探索

Step 2：组合成 2-4 字标签
        · 精算旅行家 / 信任型跟随者 / 体验探索者

Step 3：配上一个真实感的人名
        · 精算旅行家 · 李薇
        · 信任型跟随者 · 陈浩
        · 体验探索者 · 张悦

Step 4：团队投票验证
        · "听到这个名字，你知道是哪类人吗？"
```

## 五、照片和视觉元素

### 5.1 该不该放照片

| 观点 | 理由 |
|------|------|
| 该放 | 增加真实感、帮助记忆、让团队更容易共情 |
| 慎重 | 可能引入刻板印象（年龄/种族/性别的视觉暗示） |
| 建议 | 放照片但确保多样性；或用插画/图标替代真实照片 |

### 5.2 如果放照片

| 规则 | 理由 |
|------|------|
| 不用团队成员认识的人 | 避免"这不就是小王吗"的联想 |
| 不用名人 | 避免已有印象干扰 |
| 确保多样性 | 不要全是年轻白领——除非你的用户群确实如此 |
| 用库存图片或 AI 生成 | 标注"此为示意图，非真实受访者" |

## 六、Persona 优先级

不是所有 Persona 权重相同——你需要明确**对产品决策影响力的排序**：

### 6.1 Cooper 的优先级框架

| 级别 | 含义 | 对产品的影响 |
|------|------|------------|
| Primary（主要） | 产品为这个人设计，1 个 | 核心功能和体验为 TA 优化 |
| Secondary（次要） | 也要满足，但不牺牲 Primary 的体验 | 不能增加 Primary 的负担 |
| Supplemental（补充） | 需求被 Primary/Secondary 覆盖 | 不需要专门设计 |
| Negative（反面） | 明确不为这个人设计 | 有助于说"不" |

### 6.2 确定优先级的方法

| 步骤 | 做法 |
|------|------|
| 1 | 列出所有 Persona 的核心需求 |
| 2 | 检查需求冲突：哪些 Persona 的需求互相矛盾？ |
| 3 | 结合商业目标：服务哪个 Persona 最能实现业务目标？ |
| 4 | 确定 1 个 Primary——如果只能让 1 个人满意，选谁？ |

## 七、常见错误

| # | 错误 | 后果 | 预防 |
|---|------|------|------|
| 1 | Persona 写成人口统计档案 | "25-35岁女性白领"——谁都是 | 聚焦行为和目标 |
| 2 | 没有真实引语 | 缺乏可信度和共情力 | 访谈时记录金句 |
| 3 | 叙事太泛 | "她喜欢旅行"——然后呢？ | 写一个具体场景 |
| 4 | 加入虚构细节 | "她养了一只猫"——与产品无关 | 每个细节都要有数据支撑或对决策有帮助 |
| 5 | 所有 Persona 权重相同 | 团队不知道优先满足谁 | 明确 Primary / Secondary |
| 6 | 命名带价值判断 | "菜鸟用户"让人不想服务 TA | 中性、行为导向的标签 |

---

## 八、本章核心要点

1. **Persona 是给心看的，不是给大脑看的**——目标是让全团队记住并共情
2. **叙事 = 一个具体场景的完整行为序列**——不是传记或性格描述
3. **一句好引语 > 一页描述**——从访谈中挖掘金句
4. **命名要中性、可记忆、彼此可区分**
5. **明确优先级**——只能有 1 个 Primary Persona
6. **每个细节都要有数据支撑**——不加无关的虚构信息
