# T6 · Persona 生成 — 执行协议

## 触发条件
- T3（定性分析）或 T5（定量分析）产出了分群结果
- 用户直接说"帮我写 Persona"并提供了分群描述
- 用户提供了用户画像草稿要求完善

## 输入
- 分群结果（必须）：来自 T3 或 T5
- 原始引语/故事素材（可选——有则 Persona 更有血肉）
- 产品/业务背景（必须——如前面已给过则沿用）

## 执行步骤

### Step 1：为每个群生成 Persona

对每个分群，按以下顺序生成内容：

#### 1.1 命名
- **行为标签**：2-4 字，来自核心行为特征（如"精算旅行家"）
- **人名**：真实感的中文名（如"李薇"）
- 规则：中性不带评判 / 可记忆 / 彼此可区分

#### 1.2 核心引语
- 从访谈原话中选（如有）
- 没有原话则基于行为模式合理推断一句
- 标准：简洁 + 有张力 + 直接揭示动机

#### 1.3 场景故事（150-200 字）
- 写一个**具体的、连续的行为场景**
- 规则：
  - 有时间/地点/触发事件
  - 描述 TA 做了什么（动作）而非 TA 是什么人（特质）
  - 包含一个矛盾/纠结点
  - 以第三人称写
  - 如有原始访谈素材，融入真实细节

#### 1.4 结构化信息
- 核心目标（2-3 个）
- 关键行为（3-5 个）
- 痛点（2-3 个）
- 对产品的启示（应该做什么 / 不应该做什么）

#### 1.5 元数据
- 优先级：Primary / Secondary / Supplemental / Negative
- 市场占比（如有定量数据）
- 数据来源标注

### Step 2：确定优先级

在所有 Persona 生成后，确定：
- **1 个 Primary**：产品核心为 TA 设计
- **1-2 个 Secondary**：也要满足但不牺牲 Primary
- **其余为 Supplemental**
- **可选 1 个 Negative**：明确不为 TA 设计

优先级判断依据：
1. 哪个群最大？（市场规模）
2. 哪个群最能实现业务目标？（商业价值）
3. 如果两个群需求冲突，优先谁？

### Step 3：为每个 Persona 生成完整使用场景

**在卡片之外，为每个 Persona（至少 Primary + Secondary）生成 2-3 个独立的使用场景文档。**

场景不同于卡片中 150 字的"场景故事"——它是**完整的决策/使用流程还原**，可直接用于功能设计和可用性测试。

#### 使用场景写作规则

每个场景 300-500 字，结构固定：

```markdown
### 场景 [N]：[一句话标题——如"出差前夜紧急订票"]

**触发时刻**：[什么事件/状态变化让 TA 开始行动]
**环境约束**：[时间压力/设备/场所/情绪状态]

**完整行为流**：
1. [第一步动作——具体到操作级别]
2. [第二步——包含 TA 的内心判断逻辑]
3. [第三步——遇到的阻碍/犹豫]
4. [第四步——TA 的应对方式]
5. [第五步——结果与后续行为]

**关键决策点**：
- 决策 A：[在什么时刻面临选择] → [TA 选了什么 + 为什么]
- 决策 B：[...]

**成功标准**：[TA 认为这次体验"好"的标准是什么]
**失败模式**：[什么情况下 TA 会放弃/不满/流失]

**产品启示**：
- 这个场景要求产品做到：[具体功能/信息/交互]
- 如果做不到，用户会：[具体后果]
```

#### 场景类型覆盖

为每个 Persona 选 2-3 个场景，覆盖：
- **核心场景**：TA 最频繁做的事（高频刚需）
- **极端场景**：时间压力大/情绪焦虑/金额高时的行为
- **首次场景**：TA 第一次使用产品时的行为（冷启动）

### Step 4：输出完整 Persona 文档

## 产出模板

每个 Persona 一个 section，按以下格式：

```markdown
---

## 精算旅行家 · 李薇

> "同样的酒店差 200 块，不比怎么行？"

**一句话**：频繁出行但精打细算，每次预订至少比较 3 个平台才下手。

### 场景故事

周五下午 3 点，李薇在工位上收到闺蜜群消息："下周末杭州？"
她的第一反应不是搜景点——而是同时打开飞猪、携程、美团的酒店页面，
同一家酒店三个价格并排截图比较。她特别关注"优惠券能不能叠加"和
"取消政策"。10 分钟后她发了条消息："飞猪便宜 40，但只能预付。值不值？"
闺蜜说随便。她纠结了一下——万一加班呢？但 40 块差价让她最终选了预付。
下单后截图存好——如果降价，她要找客服补差价。

### 核心目标
- 用最少的钱获得满意的旅行体验
- 避免"买贵了"的后悔感
- 在有限预算内最大化出行频次

### 关键行为
- 每次预订前比较 3+ 个平台
- 关注限时促销、优惠券叠加
- 截图比价，建立价格参照
- 预订后持续关注是否降价
- 乐于在社群分享省钱攻略

### 痛点
- 比价耗费大量时间精力
- 信息分散在多个 App，无法一站式对比
- 担心选了便宜的结果体验差

### 对产品的启示
- **应该**：提供一键比价 / 价格保护 / 降价提醒
- **不应该**：隐藏价格信息 / 默认推送高价选项

### 元数据
- 优先级：**Primary**
- 市场占比：约 28%
- 数据来源：8 场深度访谈 + 500 份问卷聚类

---

### 使用场景

#### 场景 1：周末闪游比价（核心场景）

**触发时刻**：朋友群里有人发起周末出行邀约
**环境约束**：工作间隙 10-15 分钟碎片时间，手机操作

**完整行为流**：
1. 同时打开飞猪/携程/美团三个 App 搜同一酒店
2. 截图三个价格放在相册对比，心算"飞猪 + 88VIP 折扣"总价
3. 发现飞猪便宜 40 但只能预付——犹豫"万一计划变了呢"
4. 检查取消政策，发现 48 小时前免费取消 → 决定下单
5. 下单后设置降价提醒，加入"已订"收藏夹

**关键决策点**：
- 决策 A：预付 vs 到付 → 选预付（差价 > 风险成本）
- 决策 B：选平台 → 价格最低 + 取消政策最宽松

**成功标准**：最终价格比其他平台低，且有退路（可取消）
**失败模式**：发现其他平台更便宜 → 后悔 → 下次不再首选这个平台

**产品启示**：
- 要求：显示"比价结论" / 取消政策前置 / 降价提醒
- 如果做不到：用户流失到价格更透明的平台

#### 场景 2：...
```
