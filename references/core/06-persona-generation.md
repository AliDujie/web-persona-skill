# T6 · Persona 生成 — 执行协议

## 触发条件
- T3（定性分析）或 T5（定量分析）产出了分群结果
- 用户直接说"帮我写 Persona"并提供了分群描述
- 用户提供了用户画像草稿要求完善

## 输入
- 分群结果（必须）：来自 T3 或 T5
- 原始引语/故事素材（可选——有则 Persona 更有血肉）
- 产品/业务背景（必须——如前面已给过则沿用）

## 执行步骤

### Step 1：为每个群生成 Persona

对每个分群，按以下顺序生成内容：

#### 1.1 命名
- **行为标签**：2-4 字，来自核心行为特征（如"精算旅行家"）
- **人名**：真实感的中文名（如"李薇"）
- 规则：中性不带评判 / 可记忆 / 彼此可区分

#### 1.2 核心引语
- 从访谈原话中选（如有）
- 没有原话则基于行为模式合理推断一句
- 标准：简洁 + 有张力 + 直接揭示动机

#### 1.3 场景故事（150-200 字）
- 写一个**具体的、连续的行为场景**
- 规则：
  - 有时间/地点/触发事件
  - 描述 TA 做了什么（动作）而非 TA 是什么人（特质）
  - 包含一个矛盾/纠结点
  - 以第三人称写
  - 如有原始访谈素材，融入真实细节

#### 1.4 结构化信息
- 核心目标（2-3 个）
- 关键行为（3-5 个）
- 痛点（2-3 个）
- 对产品的启示（应该做什么 / 不应该做什么）

#### 1.5 元数据
- 优先级：Primary / Secondary / Supplemental / Negative
- 市场占比（如有定量数据）
- 数据来源标注

### Step 2：确定优先级

在所有 Persona 生成后，确定：
- **1 个 Primary**：产品核心为 TA 设计
- **1-2 个 Secondary**：也要满足但不牺牲 Primary
- **其余为 Supplemental**
- **可选 1 个 Negative**：明确不为 TA 设计

优先级判断依据：
1. 哪个群最大？（市场规模）
2. 哪个群最能实现业务目标？（商业价值）
3. 如果两个群需求冲突，优先谁？

### Step 3：输出完整 Persona 文档

## 产出模板

每个 Persona 一个 section，按以下格式：

```markdown
---

## 精算旅行家 · 李薇

> "同样的酒店差 200 块，不比怎么行？"

**一句话**：频繁出行但精打细算，每次预订至少比较 3 个平台才下手。

### 场景故事

周五下午 3 点，李薇在工位上收到闺蜜群消息："下周末杭州？"
她的第一反应不是搜景点——而是同时打开飞猪、携程、美团的酒店页面，
同一家酒店三个价格并排截图比较。她特别关注"优惠券能不能叠加"和
"取消政策"。10 分钟后她发了条消息："飞猪便宜 40，但只能预付。值不值？"
闺蜜说随便。她纠结了一下——万一加班呢？但 40 块差价让她最终选了预付。
下单后截图存好——如果降价，她要找客服补差价。

### 核心目标
- 用最少的钱获得满意的旅行体验
- 避免"买贵了"的后悔感
- 在有限预算内最大化出行频次

### 关键行为
- 每次预订前比较 3+ 个平台
- 关注限时促销、优惠券叠加
- 截图比价，建立价格参照
- 预订后持续关注是否降价
- 乐于在社群分享省钱攻略

### 痛点
- 比价耗费大量时间精力
- 信息分散在多个 App，无法一站式对比
- 担心选了便宜的结果体验差

### 对产品的启示
- **应该**：提供一键比价 / 价格保护 / 降价提醒
- **不应该**：隐藏价格信息 / 默认推送高价选项

### 元数据
- 优先级：**Primary**
- 市场占比：约 28%
- 数据来源：8 场深度访谈 + 500 份问卷聚类

---
```
