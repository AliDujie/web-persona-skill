# T3 · 定性分析 — 执行协议

## 触发条件
用户提供了访谈文字稿、用户笔记、用户反馈文本、客服对话记录等定性数据。

## 输入
- 文本数据（必须）：访谈稿 / 笔记 / 反馈 / 评论
- 产品背景（可选——如果之前没说过就问一句）

## 执行步骤

### Step 0：段落预筛（cheap Yes/No filter）

借鉴 deep-research-iterative 的"两阶段评估"原则：先用便宜的 Yes/No 判断过滤无关段落，再做昂贵的行为提取。

**对每个原始段落（约 100-300 字一段）做一次单问判断**：
> "这段对话/文本是否包含任何**用户行为/动机/态度/痛点**信息？"
> 答 `Yes` / `No`，不要解释。

**过滤规则**：
- `No` → 直接跳过（寒暄、自我介绍、无关闲聊、研究员独白）
- `Yes` → 进入 Step 1 做完整提取

向用户报告：
> "原始 [N] 段，预筛后保留 [M] 段含行为信息（过滤了 [K] 段闲聊/无关内容），节省 [≈%] token。"

**反模式**：跳过 Step 0 直接对全文做行为提取——长访谈稿里 30-50% 是无信息内容，浪费 token 还稀释信号。

---

### Step 1：提取行为片段

从预筛保留的段落中逐条提取**独立的行为/动机/态度/痛点片段**：

```
[P01-行为][src:interview_01.txt#para12] 每次预订前至少比较 3 个平台的价格
[P01-动机][src:interview_01.txt#para12] "同样的酒店差价可能有 200 块，不比怎么行"
[P01-痛点][src:interview_01.txt#para18] 比价费时间，希望有人帮他做好
[P02-行为][src:interview_02.txt#para3] 从不比价，朋友推荐什么平台就用什么
[P02-动机][src:interview_02.txt#para3] "花那个时间不如多玩一个地方"
```

**提取规则**：
- 每条片段只包含一个信息点
- **标注 `evidence_id`**：来源受访者 + 文件名 + 段落号（如 `src:interview_01.txt#para12`）——这是 T6/T7 做 evidence_map 的基础
- 区分行为事实 vs 态度观点 vs 痛点
- 保留原话引语（用引号标记）
- 忽略与研究目标无关的闲聊

### Step 2：识别行为变量

从所有片段中归纳"用户在哪些维度上表现出差异"：

```markdown
## 行为变量清单

| 变量名 | 维度描述 | 极端A | 极端B | evidence_count |
|--------|---------|-------|-------|----------------|
| 计划程度 | 用户提前多久开始准备 | 提前数月详细规划 | 临时起意 | 12 条 |
| 信息依赖 | 用户如何收集信息做决策 | 自己深度研究 | 依赖他人推荐 | 9 条 |
| 价格敏感 | 价格在决策中的权重 | 核心驱动因素 | 不在意 | 15 条 |
| ... | | | | |
```

**变量筛选规则**：
- 只保留有行为意义的维度（行为 > 态度 > 人口统计）
- 确保有足够变异性（至少 2 个受访者在这个维度上不同）
- 确保与产品决策相关
- evidence_count ≥ 3（至少 3 条不同受访者的片段支撑该变量）
- 最终保留 6-12 个变量

### Step 3：饱和度判断（borrowed from deep-research `<done>` signal）

在产出变量清单后，让自己回答一次：
> "已有的 [M] 个变量是否足以解释 [N] 位受访者之间所有显著的行为差异？\n
> 如果还有未覆盖的差异维度 → 列出（最多 3 条）→ 回到 Step 1 补提取\n
> 如果已饱和 → 输出 `<done>` 进入 Step 4"

**强制上限**：
- Step 1↔Step 3 的循环最多 **3 轮**
- 连续 2 轮新增变量数 < 1 → 强制 `<done>`，不再继续

向用户报告：
> "饱和度判断：[已饱和 / 还需补充 X 个维度]，本次共 [Y] 轮编码循环。"

### Step 4：亲和归类

将受访者按行为变量组合进行分群：

```markdown
## 分群过程

### 1. 每位受访者的变量打分
| 受访者 | 计划程度 | 信息依赖 | 价格敏感 | ... |
|--------|---------|---------|---------|-----|
| P01 | 高 | 自研 | 高 | ... |
| P02 | 低 | 他人 | 低 | ... |
| P03 | 高 | 自研 | 中 | ... |

### 2. 分群
- P01 + P03 + P06 → 行为相似（计划型+自研型）→ 群 A
- P02 + P05 + P08 → 行为相似（随性型+依赖型）→ 群 B
- ...
```

### Step 5：产出分群结果


## Pitfalls

| 症状 | 修复 |
|------|------|
| 跳过 Step 0 直接全文提取 → token 烧光，信号被稀释 | 严格执行 Yes/No 预筛 |
| 一轮编码就停 → 行为变量遗漏 | 至少跑 2 轮饱和度判断 |
| 编码超过 3 轮还在加变量 → 越提越细，分群无意义 | 强制 `<done>`，把多余变量记入"次要维度"而非主分群依据 |
| evidence_id 漏标或拼凑 → T7 无法机械验证 | Step 1 提取时强制带 src:[文件]#[段落]，没源就丢弃片段 |

## Verification（产出后机械检查）

- [ ] 每个分群至少 2 名受访者
- [ ] 每条行为/痛点/动机片段都有 `evidence_id`（无空白来源）
- [ ] 编码循环 ≤ 3 轮（看产出报告"编码循环"字段）
- [ ] 行为变量数 6-12（少于 6 区分度不够，多于 12 反而稀释）
- [ ] 每个变量 evidence_count ≥ 3
