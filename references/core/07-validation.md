# T7 · 验证 — 执行协议

## 触发条件
- 用户说"帮我验证这些 Persona"
- T6 完成后用户选择了验证
- 用户提供了已有 Persona 文档要求审查

## 输入
- Persona 文档（必须）
- 原始数据来源描述（可选——帮助判断数据支撑程度）

## 执行步骤

### Step 1：认知偏差自检（研究过程审计）

**在检查 Persona 内容之前，先审计产出这些 Persona 的研究过程本身是否有系统性偏差。**

基于 Kahneman 双系统理论，检查以下研究员常见偏差：

```markdown
## 研究过程偏差审计

### System 1 快速思维偏差（研究员在研究过程中可能犯的）

| 偏差类型 | 检查问题 | 危险信号 |
|---------|---------|---------|
| **确认偏误** | 研究设计是否只能证实假设、无法证伪？ | 访谈只问了"你觉得X好不好"而没有问"你什么时候不用X" |
| **可得性偏差** | 是否过度依赖容易接触到的用户样本？ | 全部受访者来自同一渠道/同一城市/同一时间段 |
| **锚定效应** | 第一批访谈是否锚定了后续所有分析方向？ | 最终 Persona 的维度和第一版假设惊人一致 |
| **代表性启发** | 是否因为一个生动案例就创建了一整个 Persona？ | 某个 Persona 只有 1-2 个数据点支撑 |
| **幸存者偏差** | 是否只研究了现有用户、遗漏了流失/未转化用户？ | 所有 Persona 都是"会使用产品的人"，没有"拒绝使用的人" |
| **群体思维** | 分析是否由一个人独立完成、缺乏交叉验证？ | 编码/聚类/命名全由同一人完成，无第二视角 |

### System 2 慢速思维应做但可能偷懒的

| 应做动作 | 检查是否做了 | 如果没做 |
|---------|------------|---------|
| **对立假设** | 有没有主动想过"如果分群完全不对，会是什么样？" | 加入 Devil's Advocate 步骤 |
| **Pre-mortem** | 有没有想过"如果这套 Persona 6个月后被废弃，原因会是什么？" | 预判失败模式 |
| **基率检验** | 各 Persona 占比是否与已知市场数据可交叉验证？ | 找外部数据对比 |
| **边界案例** | 有没有那些"哪个 Persona 都归不进去"的用户？ | 这些边界用户是新 Persona 还是噪声？ |
```

### Step 2：多维度内容审查

对每个 Persona 逐一检查以下维度：

```markdown
## Persona 审查清单

### 1. 数据支撑度
- [ ] 每个行为描述都有数据/访谈支撑？
- [ ] 引语来自真实受访者（而非虚构）？
- [ ] 市场占比有量化依据？

### 2. 行为区分度
- [ ] 用 2-3 个变量就能区分各 Persona？
- [ ] 没有两个 Persona "太像"难以区分？
- [ ] Primary Persona 的需求和 Secondary 有明确差异？

### 3. 命名偏见检查
- [ ] 命名是否中性（不含价值判断）？
- [ ] 是否避免了刻板印象（性别/年龄/地域）？
- [ ] 照片/描述是否包容多样性？

### 4. 覆盖度
- [ ] 是否有"哪个 Persona 都对不上"的已知用户？
- [ ] 是否遗漏了重要的用户群体？
- [ ] Negative Persona 是否被明确标注？

### 5. 可操作性
- [ ] 每个 Persona 都能指导具体产品决策？
- [ ] "对产品的启示"足够具体（不是"做好用户体验"这种空话）？
- [ ] 团队看完能说出"如果只满足一个人，选谁"？

### 6. 内部一致性
- [ ] 目标和行为逻辑自洽？
- [ ] 痛点与行为匹配？
- [ ] 场景故事与结构化信息一致？
```

```markdown
2. [次要修改]

### Pre-mortem：如果这套 Persona 失败了...

1. [...]

### 验证方案建议
- **最快验证**（1-2天）：找团队里直接接触用户的人（客服/销售），让他们看 Persona 卡片回答"你接触的用户里，能对应到这些人吗？比例感觉对吗？"
- **标准验证**（1周）：每个 Persona 找 2-3 个新用户做 30 分钟快速访谈，验证行为描述是否准确
- **严格验证**（2周）：让新用户做"自我归类测试"——看到去掉名字的 Persona 描述，选自己最像哪个
```

### Step 4：如果需要修改，直接修改

不是给建议——直接产出修改后的版本。如果审查发现问题，直接重写有问题的 Persona 卡片部分，标注修改点。
