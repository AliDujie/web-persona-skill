# 17 · Buyer Persona：B2B 销售视角的角色方法

> 来源：Revella, A. *Buyer Personas: How to Gain Insight into your Customer's Expectations, Align your Marketing Strategies, and Win More Business* (Wiley, 2015)；Buyer Persona Institute 公开课程；Forrester *"B2B Buyer Journey Research"* (2021/2024)。
>
> Mulder/Cooper 派 Persona 关心"用户怎么用产品"；Revella 关心一件 Mulder 不直接回答的事——"采购方怎么从『从未听说』到『签约』再到『续约』，整个决策链上有谁、何时介入、为什么选你而非对手"。本笔记基于 Revella 的 5 Rings of Buying Insight 框架与 B2B 实战经验整理。

---

## 1. 与 Mulder《赢在用户》的关系

| 维度 | Mulder（本技能默认） | Buyer Persona（本笔记） |
|---|---|---|
| 关注对象 | 产品的"使用者" | 企业采购的"决策者+影响者+使用者+把关者" |
| 输出粒度 | 1 张人物画像 | 1 张画像 + 5 Rings 决策洞察 + 决策旅程图 |
| 数据采集 | 调查/可用性测试为主 | **赢单&败单复盘访谈** (Win/Loss Interviews) 为主 |
| 适合场景 | C 端 Web 产品、注册-激活漏斗 | B2B SaaS、企业软件、长决策周期、高客单 |
| 关键问题 | "他想完成什么？" | "他为什么选了对手？什么让他改变现状？" |
| 应用部门 | 产品+设计 | 产品+市场+销售+客户成功（CS） |

> 💡 **互补立场**：Mulder 让设计师懂用户；Revella 让销售&市场懂买家。两套并存可——使用者画像 (User Persona) + 买家画像 (Buyer Persona) 是两份不同文档，避免混在一起。

---

## 2. 五大购买洞察 (5 Rings of Buying Insight)

Revella 的核心贡献：把 B2B 决策抽象为 5 个可访谈、可复用的洞察维度。

| Ring | 中文 | 关键问题 | 用途 |
|---|---|---|---|
| **1. Priority Initiative** | 优先动议 | 是什么事件触发他**现在**寻找解决方案？为什么不是去年？ | 找触发事件 (Trigger) |
| **2. Success Factors** | 成功要素 | 项目成功对他个人/团队意味着什么？衡量指标？ | 找价值主张 (Value Prop) |
| **3. Perceived Barriers** | 感知障碍 | 他对你的产品/品类有什么疑虑、恐惧、负面经历？ | 反对意见处理 (Objection Handling) |
| **4. Decision Criteria** | 决策标准 | 候选方案对比时，他列了哪些标准？权重？ | 竞争话术 + Demo 重点 |
| **5. Buyer's Journey** | 买家旅程 | 从触发到签约，他走过哪些阶段？每阶段他做什么、找谁、看什么？ | 内容地图 + 销售剧本 |

> ⚠️ Revella 的纪律：**永远从 Buyer's Journey 倒推 Priority Initiative**——只有锁定真实触发事件，前 4 个 Ring 才有意义。理论触发与真实触发常天差地别。

---

## 3. 5 Rings 访谈技术 (The Probing Question)

Revella 主张**只问开放式追问，不问封闭式确认**。30-45 分钟的电话/视频 Win/Loss 访谈，问 6-8 个核心问题足够。

### 经典开场白
> "请把我带回到您**第一次意识到**需要解决这个问题的那一刻。当时发生了什么？"

### 5 类追问句式

| 类别 | 句式 | 目的 |
|---|---|---|
| 时间钩 | "在那之前呢？""然后呢？" | 拉出时间线 |
| 角色钩 | "那时谁还参与了？" | 识别决策链上的其他人 |
| 替代钩 | "您有没有考虑过别的做法？为什么没选？" | 揭示竞争对手 + 决策标准 |
| 担忧钩 | "您当时担心什么会出错？" | 揭示 Perceived Barriers |
| 判定钩 | "在某某关头，您是怎么决定要 / 不要继续的？" | 揭示 Decision Criteria |

> **禁止**：引导性问题（"您是不是因为价格便宜才选了 A？"）、把自家产品名带出（"您觉得我们 vs 竞品如何？"）。中立观察者立场是关键。

## 4. 决策链：Buyer 不止一个人

B2B 平均决策参与人 = 6.8 人（Forrester 2024）。Revella 把决策链拆分为 5 类角色：

| 角色 | 中文 | 行为特征 | 内容偏好 |
|---|---|---|---|
| **Champion** | 冠军 | 推动者；把方案介绍给团队 | 案例、对比表、ROI 计算器 |
| **Decision Maker** | 决策者 | 最终签字；通常 VP/CXO | 高度概要、商业洞察、风险文档 |
| **Influencer** | 影响者 | 提出意见；同事、合作伙伴 | 行业报告、专家观点 |
| **Gatekeeper** | 把关者 | 拦截供应商；采购、法务、合规、IT | 安全白皮书、合规证明、SOC 2 |
| **End User** | 最终用户 | 实际使用产品 | 试用、Demo、培训资源 |

> **常见错误**：B2B 销售只面向 Decision Maker，忽视 Gatekeeper（采购/IT），导致后期被否决；只面向 End User，忽视 Decision Maker，导致试用很爽但买不下来。

## 5. Buyer Persona 文档模板（推荐 1-2 页）

```
姓名：Mark, IT 总监
公司侧写：800-1500 人制造业，年营收 $5亿
角色：Decision Maker（5 Buyer Roles）

🚨 触发事件 (Priority Initiative)
- 现有 ERP 维护合同到期 / 一次重大故障 / 合规审计
- 关键引语："如果再来一次故障，我下个月就走人。"

🎯 成功标准 (Success Factors)
- 个人：避免重大故障；为下一次 IT 战略汇报赢得 CEO 信任
- 团队：上线后 6 个月内系统可用率 ≥ 99.5%
- 公司：3 年 TCO 比现状下降 20%

🚧 感知障碍 (Perceived Barriers)
- "你们 SaaS 数据合规可信吗？"
- "去年某厂迁移失败了 9 个月，我们承受不起"
- "员工抗拒新系统培训"

⚖️ 决策标准 (Decision Criteria)
1. 同行业可参考案例（权重 30%）
2. 数据安全 + SOC 2 / ISO 27001（权重 25%）
3. 上线时间 ≤ 6 个月（权重 20%）
4. 培训配套 + 中文支持（权重 15%）
5. 价格（权重 10%）

🛤 买家旅程 (Buyer's Journey)
| 阶段 | 时间 | 行为 | 我们做什么 |
| 触发 | T0 | 出故障 / 听说同行新系统 | SEO + 行业报告 |
| 学习 | T0-2月 | Google + Gartner + 同行问询 | 白皮书 + 案例 + 分析师报告 |
| 评估 | T2-4月 | RFP 询价 + Demo + POC | 销售工程师 + ROI 工具 |
| 选择 | T4-5月 | 内部 review + 法务谈判 | 安全白皮书 + 合同模板 |
| 签约 | T5月 | 总裁/董事会签字 | 高管对接 + 风险缓释 |
| 上线 | T5-9月 | 实施 + 培训 | 客户成功 + 培训资源 |
| 续约 | T18月起 | NPS + 复购 | QBR + 续约谈判 |
```

## 6. Win/Loss 访谈：Revella 派的核心引擎

| 项 | 内容 |
|---|---|
| 对象 | 已签约（Win）+ 已流失（Loss）客户，6 个月内决策 |
| 数量 | 8-12 名/Persona，Win/Loss 1:1 比例 |
| 形式 | 30-45 分钟电话/视频，第三方/中立访谈员，**不能是销售人员**（受访者会客气化） |
| 问题数 | 6-8 道核心 + 自然追问 |
| 报酬 | $50-200 礼品卡（C 端可省，B2B 必给） |
| 输出 | 转写 + 5 Rings 编码 + 引语库 (Quote Bank) |
| 频率 | 季度滚动；新 Persona 至少 8-12 名；老 Persona 每年补 4-6 名 |

### 6 个经典核心问题
1. 请回顾您**第一次意识到**需要解决该问题的那一刻。
2. 在评估各家方案时，您把哪些列为候选？为什么？
3. 您当时**最担心**什么会出错？
4. 在某某关头，您是怎么决定**继续**的？
5. 您身边还有谁参与了这次决策？他们的角色是？
6. 如果回到当初，您会做什么不同的选择？

## 7. 反模式 (Anti-patterns)

| 反模式 | 症状 | 后果 |
|---|---|---|
| **猜测 Persona** | 团队拍脑袋写 Buyer Persona，无访谈 | 内容、销售话术全失焦 |
| **销售自访谈** | 销售跟客户做 Win/Loss | 受访者敷衍、回避真因 |
| **只看 Win 不看 Loss** | 仅访问已签客户 | 看不到流失原因，无法改进 |
| **Persona 无 Trigger** | 5 Rings 缺 Priority Initiative | 内容营销发力点错 |
| **Persona 太多** | 给每个职级都做画像 | 销售记不住，市场内容稀释 |
| **Persona 与 ICP 混淆** | 把"理想客户公司画像 (ICP)"当 Persona | 失去人格维度，销售剧本写不出 |

---

## 8. ICP vs Buyer Persona vs User Persona：三者的边界

| 概念 | 中文 | 单位 | 用途 |
|---|---|---|---|
| **ICP** (Ideal Customer Profile) | 理想客户画像 | **公司** | 营销定位、销售线索过滤 |
| **Buyer Persona** | 买家画像 | **决策链上的人** | 销售剧本、内容地图 |
| **User Persona** | 用户画像 | **使用产品的人** | 产品设计、UX 决策 |

> B2B 项目通常需要 **1 个 ICP + 2-4 个 Buyer Persona + 1-2 个 User Persona**。三类同时存在，分别服务不同部门。

---

## 9. 何时使用 Buyer Persona

✅ 用：
- B2B 软件/服务，决策周期 ≥ 1 个月
- 客单价 ≥ $5K/年
- 销售周期内有 RFP / Demo / POC 流程
- 多人决策（≥3 人参与）
- 内容营销/SEO/Outbound 是主要拉新手段

⛔ 不用：
- C 端冲动消费（< 5 分钟决策）→ 转用 Mulder Web Persona
- 个人使用工具（决策人=用户）→ 仅做 User Persona
- 决策周期 < 1 周 → 5 Rings 信息密度不够

## 本部分核心要点总结

| 要点 | 一句话 |
|---|---|
| Buyer ≠ User | B2B 必须分开做画像，决策者和使用者诉求不同 |
| 5 Rings 是核心 | 每个 Ring 都靠 Win/Loss 访谈采集，不靠猜 |
| Trigger 决定一切 | 没有真实触发事件，营销内容找不到落点 |
| 决策链 ≥ 6 人 | 销售/市场要同时设计触达 5 类角色的内容 |
| Win/Loss 必须中立 | 销售不能访谈自己的客户 |
| 与 ICP/User 三层并存 | 不是替代，是同时存在 |
