# 19 · 服务设计 Persona：嵌入旅程与蓝图的角色方法

> 来源：Stickdorn, M., Hormess, M., Lawrence, A. & Schneider, J. *This Is Service Design Doing* (O'Reilly, 2018)；Polaine, A., Løvlie, L. & Reason, B. *Service Design: From Insight to Implementation* (Rosenfeld, 2013)；Service Design Network *"Service Design Impact Report"* (2023, 2024)；Polaine *Service Blueprint Workshop* (2022)。
>
> 当 Persona 单独存在时，它告诉你"用户是谁"；当 Persona 嵌入服务旅程 + 服务蓝图时，它告诉你"用户在每一刻遇到什么、谁在背后支撑、卡点在哪里"。本笔记基于服务设计派的 4 大产物 + 6 类细分 Persona 整理。

---

## 1. 与 Mulder《赢在用户》的关系

| 维度 | Mulder（本技能默认） | 服务设计 Persona（本笔记） |
|---|---|---|
| 关注边界 | 数字界面 / Web 内 | 全渠道 / 触点（线上+线下+电话+邮件+人） |
| 单位 | 1 张人物画像 | 画像 + Journey Map + Blueprint + Stakeholder Map（4 件套） |
| 时间维度 | 静态画像 | 旅程阶段（前/中/后） + 情绪曲线 |
| 适合场景 | 单一数字产品 | 服务型业务（银行、医疗、零售、酒旅、政务） |
| 核心关切 | 是否完成任务 | 体验是否一致、跨触点是否协同 |
| 失败模式 | UI 难用 | 触点割裂、前台对承诺、后台不知情 |

> 💡 **互补立场**：Mulder 的 Persona 是"主角"；服务设计把舞台、配角、幕后剧务、剧本、灯光全部画清——Persona 不是孤立角色，而是关系网络的一个节点。

---

## 2. 服务设计的 4 大产物 (The Big Four)

| 产物 | 说明 | 与 Persona 的关系 |
|---|---|---|
| **Personas** | 多类型用户画像 | 主角清单 |
| **Customer Journey Map** | 用户在时间轴上的所有触点+情绪+痛点 | Persona 的"剧本" |
| **Service Blueprint** | 前台触点 + 后台流程 + 支撑系统的全景图 | Persona 体验背后的"工厂" |
| **Stakeholder Map** | 所有利益相关方关系图（含内部团队、合作伙伴） | Persona 之外的"配角" |

> ⚠️ 缺一即漏：只有 Persona+Journey 看不到后台问题；只有 Blueprint 看不到情绪曲线；任一缺失都会让设计落空。

---

## 3. 服务设计的 6 类 Persona

| 类型 | 含义 | 示例（医院场景） |
|---|---|---|
| **Customer Persona** | 端用户/患者 | 来看病的患者本人 |
| **Companion Persona** | 陪同者 | 陪诊家属 |
| **Frontline Persona** | 前线员工（直接接触客户） | 接诊护士、前台 |
| **Backstage Persona** | 后台员工（不直接接触但影响体验） | 检验科技师、IT 运维 |
| **Partner Persona** | 合作方 | 第三方影像中心 |
| **Decision Maker Persona** | 内部决策者 | 院长、信息科主任 |

> 服务型项目通常需要 **3-6 类 Persona** 同时设计——只盯客户会让员工累垮，只盯员工会让客户失望，只盯院长会让一线起义。

## 4. Customer Journey Map：Persona 的剧本

### 4.1 5 行结构（推荐模板）

| 行 | 内容 |
|---|---|
| 1. 阶段 (Stages) | Awareness → Consideration → Purchase → Use → Loyalty |
| 2. 行动 (Actions) | 用户每阶段做什么 |
| 3. 触点 (Touchpoints) | 在哪个媒介/位置（App / 门店 / 电话 / 邮件 / 人） |
| 4. 情绪 (Emotions) | 1-5 分情绪曲线（或表情符号） |
| 5. 痛点 & 机会 (Pain & Opp) | 此刻为什么挫败 / 设计发力点 |

### 4.2 5 类 Moments of Truth（关键真相时刻）

服务设计派把以下 5 个时刻识别为最关键：

| 时刻 | 描述 | 设计权重 |
|---|---|---|
| **Zero MoT** | 接触品牌前在网上搜资料 | ★★★（决定要不要进） |
| **First MoT** | 第一次接触/购买 | ★★★★ |
| **Second MoT** | 使用中遇到问题 → 客服触点 | ★★★★★（决定留存） |
| **Ultimate MoT** | 极端事件（重大成功/严重失误） | ★★★★★（决定口碑） |
| **Recovery MoT** | 失败后的恢复体验 | ★★★★（化危为机） |

> **服务设计黄金率**：在 Recovery MoT 上一分投入，胜过在 First MoT 上五分投入。

## 5. Service Blueprint：Persona 体验背后的工厂

### 5.1 5 条横线结构

```
1. Customer Actions       客户行为
   ─────────── Line of Interaction（互动线）
2. Frontstage Actions     前台员工/界面行为
   ─────────── Line of Visibility（可见线）
3. Backstage Actions      后台员工行为
   ─────────── Line of Internal Interaction（内部互动线）
4. Support Processes      支撑系统/流程
   ─────────── Line of Implementation（实施线）
5. Physical Evidence      物理证据/触点制品
```

### 5.2 4 类失败可被蓝图直接发现

| 失败类型 | 蓝图症状 |
|---|---|
| **触点割裂** | 同一阶段跨触点信息不同步 |
| **前后台脱节** | 前台承诺后台无法兑现 |
| **支撑缺位** | 后台行为没有系统/流程支撑，靠员工记忆 |
| **物证矛盾** | 邮件 vs 短信 vs 网站措辞不一 |

## 6. 操作流程（端到端 8 步）

| 步 | 动作 | 输出 |
|---|---|---|
| 1 | Stakeholder 工作坊：列所有相关方 | Stakeholder Map |
| 2 | 决定 6 类 Persona 中做哪几类 | Persona 清单 |
| 3 | 民族志 / Shadowing / 访谈采集 | 原始数据 |
| 4 | 生成 Persona 画像（Mulder/Cooper 法均可） | Persona 卡片 |
| 5 | 为主 Persona 绘制 Journey Map（覆盖全阶段） | Journey Map |
| 6 | Journey 上识别 5 个 MoT，标记痛点 | MoT 清单 |
| 7 | 痛点 = 蓝图入口；逐痛点画 Service Blueprint 切片 | Blueprint |
| 8 | 共创工作坊：与一线员工+客户共同迭代 | 改进方案 |

> 服务设计的纪律：**研究室画的 Persona 不算数，员工和客户共同确认才算数。**

---

## 7. 工作坊：Service Safari & Shadowing

### 7.1 Service Safari（服务漫游）
- **做什么**：团队成员**亲自**走客户旅程（去医院挂号、去银行开户、去酒店登记）
- **用时**：2-4 小时
- **产出**：第一手痛点笔记 + 照片/录音
- **目的**：从"研究他们"到"我经历过"的同理心跃迁

### 7.2 Shadowing（影子观察）
- **做什么**：研究员跟随真实客户/员工 1-3 小时，不打扰
- **用时**：每观察对象 1 天
- **产出**：行为时间线 + 关键事件 + 体感
- **要点**：观察"小动作和说话停顿"——抱怨往往不是直接说出来的

## 8. 反模式 (Anti-patterns)

| 反模式 | 症状 | 后果 |
|---|---|---|
| **只画 Customer 不画 Frontline** | Journey 漂亮，员工抱怨 | 一线抗拒，方案落不了地 |
| **Journey 没有情绪曲线** | 全是行为列表 | 看不到关键发力点 |
| **Blueprint 不到 Support Line** | 前后台画了但底层流程缺 | 设计完成系统跟不上 |
| **MoT 全是 First Touch** | 都关心"开门红"忽视恢复 | 一次失败品牌崩塌 |
| **共创只在墙上** | 工作坊后没有 owner 跟进 | 便利贴成装饰，问题未解决 |
| **数字 Persona 画线下旅程** | 团队拿 Web Persona 画银行实体网点 | 触点假大空 |

---

## 9. 何时使用服务设计 Persona

✅ 用：
- 服务型业务（医疗、银行、酒旅、零售、政务、教育）
- 跨渠道体验（线上+线下+电话+人）
- 客诉率高、NPS 难提升
- 内部部门壁垒（数字团队 vs 门店 vs 客服）
- 整合多触点品牌战略

⛔ 不用：
- 纯数字产品 + 单一触点 → Mulder 即可
- MVP 阶段 + 资源有限 → 转用 Lean UX
- 研究只服务设计师，不服务业务 → 服务设计的本质是组织变革

## 本部分核心要点总结

| 要点 | 一句话 |
|---|---|
| 4 件套缺一不可 | Persona + Journey + Blueprint + Stakeholder |
| 6 类 Persona | 客户/陪同/前台/后台/合作/决策——多角度并行 |
| MoT 决定权重 | 5 个关键时刻，Recovery 优先于 First |
| Blueprint 5 条横线 | 客户行为↔前台↔后台↔流程↔物证 |
| 共创非装饰 | 工作坊必须有 owner 与跟进 |
| Safari/Shadowing 必做 | 团队亲历 → 同理心跃迁 |
| 服务设计 = 组织变革 | 不只是设计，更是流程与文化 |
