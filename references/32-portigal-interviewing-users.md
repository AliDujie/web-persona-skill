## 一、核心定位

Portigal 是"用户访谈方法论"的教科书级标准。本书回答一个极其实操的问题：**怎样从一个真实的人嘴里，获取他们自己都未必能直接说出的需求/行为/动机**。与 Persona Skill 的关系——Persona 的质量天花板就是访谈质量的天花板。

## 二、访谈六阶段模型

Portigal 将完整访谈拆为六个递进阶段：

### 2.1 六阶段

| # | 阶段 | 目标 | 典型时长 |
|---|---|---|---|
| 1 | Warm-up / Introduction | 建立 Rapport、说明保密 | 5 min |
| 2 | Dream Questions | 大开口探索：描述一天/一个理想 | 10 min |
| 3 | Transition Questions | 从抽象到具体 | 5 min |
| 4 | Deep-Dive / Core | 事件重建(Critical Incident)、任务流复盘 | 30 min |
| 5 | Retrospective / Reflection | 参与者自我归因 | 5-8 min |
| 6 | Wrap-up & Rapport Exit | 感谢、后续联系方式、participant gift | 2-3 min |

### 2.2 黄金比例

- 倾听 : 说话 = **80 : 20**（研究者话占比不超 20%）
- Silence Rule：问出问题后**至少等 5 秒**再追问；沉默≠尴尬，是对方在组织深层记忆

## 三、提问技术栈（Question Repertoire）

### 3.1 六大提问类型

| 类型 | 示例 | 使用场景 |
|---|---|---|
| Grand Tour | "带我走一遍你上次订票的全过程" | Core 阶段开头 |
| Contrast | "这次和上次有什么不一样？" | 探测差异认知 |
| Native Language | "你们内部管这个叫什么？" | 采集行话、术语 |
| Teach Me | "你能教我怎么做这件事吗？" | 还原操作心智模型 |
| Projection | "如果这个工具消失了，你会怎么办？" | 探测真实依赖 |
| Show Me | "你能打开手机给我看看吗？" | Contextual Inquiry 混合 |

### 3.2 追问（Probing）三层

```
L1 · Echo Probe     → 重复对方最后几个关键词（"你说的'卡住了'是指？"）
L2 · Elaboration    → "能多说一点吗？""后来怎样了？"
L3 · Clarification  → "你刚才提到三个步骤，我理解的是… 对吗？"
```

### 3.3 问题雷区（Anti-Patterns）

| 反模式 | 问题 | 正确替代 |
|---|---|---|
| Leading Question | "你是不是觉得加载太慢了？" | "你怎么看加载这件事？" |
| Double-barreled | "你觉得功能多不多，好不好用？" | 拆成两个独立问题 |
| Jargon-loaded | "你对我们的 IA 满意吗？" | "你怎么找到想要的东西？" |
| Why-chain | "为什么？为什么？为什么？" | 改用 "What happened next?" 叙事链 |
| Binary | "你用过X吗？" | "跟我聊聊你和X的经历" |

## 四、Rapport Building 框架

### 4.1 Rapport 四层

```
Layer 1 · Physical Safety    → 环境、座位、距离
Layer 2 · Emotional Safety   → 保密承诺、"没有对错答案"
Layer 3 · Cognitive Trust     → 展示你做过功课（"我看到你在XX公司…"）
Layer 4 · Shared Humanity     → 适度自我暴露、幽默、共鸣点
```

### 4.2 Rapport Killers

- 一进场就打开笔记本电脑挡住眼神
- 中途查手机
- 打断对方正在讲的故事
- 评价式回应（"哦那很好！"→ 应改为中性确认 "嗯嗯，然后呢"）

## 五、Research Debrief（数据闭环）

### 5.1 三阶段归档

| 阶段 | 时间点 | 输出 |
|---|---|---|
| Field Debrief | 当天访谈结束后 30 min | 手写便签/语音备忘 |
| Topline Summary | 48h 内 | 1 页 bullet（发现+引文+情绪标记） |
| Full Analysis | 全部访谈完成后 | 编码→主题→Persona 映射 |

### 5.2 Topline Summary 模板

```markdown
## Participant #P03 — [代称]
**日期**: 2026-05-28 | **时长**: 55 min | **场景**: 远程 Zoom

### Top 3 Insights
1. …（附原话 verbatim）
2. …
3. …

### Surprise / Tension
- 与假设冲突的点：…

### Persona Hypothesis Implication
- 可能属于 [Persona X]，但在 [领域] 的行为更接近 [Persona Y]

### Follow-up Needed
- [ ] 验证 …
```

```
                                         │ Persona Draft  │
                                         │ (clustering.py)│
                                         └────────────────┘
```

### 6.2 行为变量提取规则

从访谈中提取的不是"人口统计标签"，而是**行为维度**：

| 维度类型 | 示例 |
|---|---|
| Activity（做什么） | "每天早上打开3个比价网站" |
| Attitude（怎么想） | "便宜才是硬道理" |
| Aptitude（能力水平） | "熟练使用VPN翻墙" |
| Motivation（为什么做） | "给孩子最好的旅行体验" |
| Skill/Tool（用什么） | "只用手机、从不用电脑" |

## 七、远程访谈特别注意事项（2nd Edition 新增）

| 维度 | 面对面 | 远程 |
|---|---|---|
| Rapport 建立 | 自然（环境暗示） | 需刻意：提前5min闲聊 |
| 非言语线索 | 全身姿态可读 | 仅面部+声调 |
| Show Me | 直接看实物 | 需屏幕共享+手机镜头 |
| 技术风险 | 低 | 高：网络/音频/录制失败 |
| Session 时长 | 60-90 min | 45-60 min（疲劳更快） |
| 多地时区 | N/A | 必须在日历邀请写清时区 |

## 八、反模式检查清单

| # | 反模式 | 后果 | 修复 |
|---|---|---|---|
| 1 | "Tourist" 式访谈 | 走马观花、无深度 | 用 Critical Incident 锚定具体事件 |
| 2 | Script Slavery | 僵硬、错过惊喜信号 | Protocol 只做 70% 覆盖率，30% 即兴 |
| 3 | Rapport Without Boundary | 变成朋友聊天、离题 | 设定 Time Box + Pivot 句式 |
| 4 | Analysis Paralysis | 30 次访谈做完迟迟不输出 | 强制 48h Topline，边做边归纳 |
| 5 | Solo Researcher | 一人解读偏见累积 | Pair Debrief / Team Listening Session |
| 6 | Leading Confirmation | 只找支持假设的证据 | 每轮 Debrief 写"最意外发现" |

## 本部分核心要点总结

1. 访谈不是问答——是**引导对方重建经历**的过程（Grand Tour + Critical Incident）
2. 提问质量 > 提问数量：6 类提问 + 3 层追问构成完整武器库
3. Rapport 是手段不是目的：有边界的信任 > 无限制的亲近
4. 48h Topline 是防止数据烂在硬盘里的关键纪律
5. 远程访谈不是面对面的"降级版"——需要独立的技术准备和节奏设计
6. 访谈输出应直接映射到 Persona 的行为变量矩阵（Activity/Attitude/Aptitude/Motivation/Skill）
